**バージョン**: 1.0  
**作成日**: 2026-08-18  
**テストエンジニア**: Copilot test-engineer  
**ステータス**: 完成

## 1. 概要

本ドキュメントは、Umami のウェブサイトメモ機能（US-201）について、Playwright を用いた E2E テスト設計を定義します。

**テスト対象の主要機能**:
- ウェブサイト詳細設定画面でのメモ入力・編集・保存
- ウェブサイト一覧でのメモ表示・省略表示
- メモ変更権限の制御
- 既存メモなしウェブサイトの互換性

---

## 2. テスト戦略

### 2.1 テストピラミッド

```
    ┌─────────────────────┐
    │  E2E テスト (UI)    │  ← 本設計の対象
    │   クリティカル      │
    │   ユーザーフロー    │
    └─────────────────────┘
            ▲
    ┌─────────────────────┐
    │  統合テスト (API)   │  ← 既に実装済み
    │   バリデーション    │     (validation.test.ts)
    └─────────────────────┘
            ▲
    ┌─────────────────────┐
    │   単体テスト        │  ← 既に実装済み
    │   ロジック・関数    │     (formatNote.test.ts)
    └─────────────────────┘
```

**戦略**:
- **E2E は重要フロー**に集中: メモの入力→保存→確認、詳細↔一覧の整合性
- **バリデーション・権限は統合テストで検証済み** → E2E では主に UI 操作フロー確認
- **単体テストで基本ロジック** → E2E では統合されたユーザー体験を検証

### 2.2 フレーキー対策（安定性重視）

- **セレクタ**: `data-test-id` ベースで、CSS クラスに依存しない
- **待機**: Playwright の自動待機を活用（明示的な sleep を排除）
- **テストデータ**: 各テストで独立して用意・後始末（並列実行対応）
- **タイムアウト**: 適切に設定（ネットワーク遅延考慮）

## 4. テストシナリオ

### S-1: メモ入力・保存（正常系）

**前提**: ウェブサイト詳細設定画面が表示されている  
**操作手順**:
1. メモ入力フィールドに「本番環境、Alice が管理」と入力
2. 「保存」ボタンをクリック

**期待結果**:
- メモが保存され、確認メッセージが表示される
- 入力フィールドにメモが表示される

**対応受入条件**: 1-1  
**実装例**: `test('enters and saves a memo')`

---

### S-2: メモに改行・特殊文字を含める

**前提**: 詳細設定画面が表示されている  
**操作手順**:
1. メモに改行・特殊文字（例：`本番/検証 - 用途: API テスト`）を入力
2. 保存

**期待結果**:
- メモが正常に保存される
- 改行や特殊文字が保持される

**対応受入条件**: 1-1（拡張ケース）

---

### S-3: メモ編集（既存メモを更新）

**前提**: メモが既に保存されている  
**操作手順**:
1. メモ入力フィールドを編集（例：「本番環境」→「本番環境・重要」）
2. 保存

**期待結果**:
- 新しいメモに更新される
- 確認メッセージが表示される

**対応受入条件**: 1-2  
**実装例**: `test('edits an existing memo')`

---

### S-4: メモクリア（削除）

**前提**: メモが保存されている  
**操作手順**:
1. メモ入力フィールドを空にする
2. 保存

**期待結果**:
- メモが削除される（NULL として保存）
- 一覧でメモなしサイトとして表示される

**対応受入条件**: 1-4（空の場合）  
**実装例**: `test('clears a memo')`

---

### S-5: メモ永続化（ページリロード）

**前提**: メモが保存されている  
**操作手順**:
1. ウェブサイト詳細設定画面でメモが表示されている
2. ブラウザをリロード（F5）
3. 同じサイトの詳細設定画面を再度開く

**期待結果**:
- 保存されていたメモが表示される
- リロード後もメモが消失していない

**対応受入条件**: 1-5  
**実装例**: `test('memo persists after page reload')`

---

### S-6: ウェブサイト一覧でメモ表示

**前提**: 複数のウェブサイトが存在し、複数のメモが設定されている  
**操作手順**:
1. ウェブサイト一覧ページを表示

**期待結果**:
- メモが設定されているサイトについて、メモ列に内容が表示される
- メモ列が表示されている

**対応受入条件**: 2-1  
**実装例**: `test('displays memos in website list')`

---

### S-7: メモ省略表示（長いメモ）

**前提**: 100 文字を超える長いメモが設定されたサイトが存在  
**操作手順**:
1. ウェブサイト一覧を表示

**期待結果**:
- メモが省略表示される（100 文字 + "..."）
- ツールチップで全文が表示される（オプション）

**対応受入条件**: 2-2  
**実装例**: `test('truncates long memos in list')`

---

### S-8: 一覧↔詳細設定画面の一貫性

**前提**: 一覧でメモを確認後、詳細設定画面を開く  
**操作手順**:
1. ウェブサイト一覧でメモを確認
2. 該当サイトの「編集」ボタンをクリック
3. 詳細設定画面でメモを確認

**期待結果**:
- 一覧に表示されていたメモと、詳細設定画面のメモが同じ内容である

**対応受入条件**: 2-4  
**実装例**: `test('memo in list matches memo in detail view')`

---

### S-9: 文字数上限エラー（501 文字以上）

**前提**: 詳細設定画面が表示されている  
**操作手順**:
1. 501 文字以上のテキストを入力
2. 保存ボタンをクリック

**期待結果**:
- 保存が拒否される
- エラーメッセージが表示される（例：「メモは 500 文字以内で入力してください」）
- 入力フィールドの内容は保持される

**対応受入条件**: 1-3  
**実装例**: `test('rejects memo exceeding 500 characters')`

---

### S-10: ページアクセス権限エラー

**前提**: ウェブサイト設定変更権限がないユーザーでログイン  
**操作手順**:
1. ウェブサイト詳細設定画面にアクセスしようとする

**期待結果**:
- 401 Unauthorized またはリダイレクト
- 詳細設定画面にアクセスできない

**対応受入条件**: 3-1  
**実装例**: `test('denies access without permission')`

---

### S-11: API 権限チェック（メモ更新）

**前提**: 権限なしユーザーが API を直接呼び出す  
**操作手順**:
1. POST /api/websites/{websiteId} に権限なしユーザーで note を更新しようとする

**期待結果**:
- HTTP 401 が返される
- エラーメッセージが返される

**対応受入条件**: 3-2  
**実装例**: `test('api returns 401 for unauthorized user')`

---

### S-12: メモなしサイト表示（互換性）

**前提**: メモが未設定のウェブサイトが存在  
**操作手順**:
1. ウェブサイト一覧を表示
2. メモなしサイトを確認

**期待結果**:
- エラーなく表示される
- メモ列は空白または「-」と表示される

**対応受入条件**: 4-1, 2-3  
**実装例**: `test('displays website with no memo')`

---

### S-13: 既存サイト編集（互換性）

**前提**: メモが NULL のウェブサイト  
**操作手順**:
1. 詳細設定画面を開く
2. 他のフィールド（名前など）を編集
3. 保存

**期待結果**:
- エラーなく編集できる
- メモ入力フィールドは空として表示される

**対応受入条件**: 4-2  
**実装例**: `test('edits existing website with null memo')`

## 6. Playwright テスト実装ガイドライン

### 6.1 ファイル構成

```
tests/e2e/
├── fixtures.ts              ← テスト用データ（メモデータ追加）
├── helpers.ts               ← ヘルパー関数（メモ操作関数追加）
├── e2e-US-201.spec.ts       ← US-201 E2E テスト（本実装）
├── website.spec.ts          ← 既存テスト
└── ... その他
```

### 6.2 セレクタ戦略

**優先順位**:
1. **`getByTestId()`**: 最も推奨（role・label 属性を使う）
2. **`getByRole()`**: アクセシビリティ対応
3. **`getByLabel()`**: フォーム要素
4. **`getByText()`**: ボタン・リンク（避ける）
5. **CSS クラス**: 最後の手段（脆い）

**例**:
```typescript
// ✅ 推奨
await page.getByTestId('textarea-note').fill('memo');

// ✅ 許可
await page.getByLabel(/Memo/i).fill('memo');

// ❌ 避ける
await page.locator('.memo-input').fill('memo');
```

### 6.3 待機と自動待機

**Playwright の自動待機を活用**:
```typescript
// ✅ 自動待機あり（推奨）
await page.getByTestId('button-submit').click();
await expect(page.getByText('Saved')).toBeVisible();

// ❌ 明示的な sleep（排除）
await page.waitForTimeout(1000);
```

### 6.4 テストデータの生成と後始末

**各テスト独立**:
```typescript
test('test case', async ({ page, request }) => {
  const auth = await loginPage(page, request);
  
  // Setup: テストデータ作成
  const website = await addWebsite(request, auth, 'Test Site', 'test.com');
  
  // Test: 操作
  await page.goto(`/settings/websites/${website.id}`);
  await page.getByTestId('textarea-note').fill('Test memo');
  await page.getByTestId('button-submit').click();
  
  // Verify: 確認
  await expect(page.getByTestId('textarea-note')).toHaveValue('Test memo');
  
  // Cleanup: 後始末
  await deleteWebsite(request, auth, website.id);
});
```

### 6.5 フレーキー対策チェックリスト

- [ ] セレクタは `data-test-id` ベース
- [ ] 明示的 `sleep` なし（自動待機使用）
- [ ] テスト間の依存性なし（各テスト独立）
- [ ] ネットワーク遅延考慮（適切なタイムアウト）
- [ ] 後始末（cleanup）実装
- [ ] 並列実行対応
