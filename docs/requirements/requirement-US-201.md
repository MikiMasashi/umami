# 要件定義書：US-201 ウェブサイト管理メモ機能

## 1. 背景・目的・スコープ

### 背景
Umami に登録するウェブサイトが増えると、名前とドメインだけでは、どれが本番環境でどれが検証用か、誰の依頼で作られたのかが分からなくなる問題が発生している。

### 目的
サイト運用者がウェブサイトに対して自由記述のメモを保存・管理できることで、サイト一覧から各サイトの役割や状態を素早く把握し、サイト管理の効率を向上させる。

### 成功指標
- ウェブサイト設定画面でメモを入力・編集・保存でき、永続化される
- ウェブサイト一覧でメモが表示される（長い場合は省略）
- 既存のメモが設定されていないサイトでもエラーなく動作する
- メモを編集する権限がないユーザーは変更できない

### 対象ユーザー
- Umami のサイト管理者・運用者
- 複数のウェブサイトを登録・運用している人

## 2. 機能要件

### 2.1 ユーザーストーリー・受け入れ条件

#### US-201-1: ウェブサイト設定画面でメモを入力・編集・保存する

**ユーザーストーリー**
> サイト運用者として、ウェブサイト設定の詳細画面でメモを入力・編集・保存したい。
> なぜなら、そのサイトの役割や背景を記録しておきたいから。

**受け入れ条件**

```gherkin
Feature: ウェブサイト設定画面でのメモ管理

  Scenario: メモを新規入力して保存する
    Given ウェブサイト設定の詳細画面を表示しており、メモが未入力の状態
    When メモ入力欄に内容を入力して「保存」ボタンをクリック
    Then メモが保存されたことを示すフィードバック（成功メッセージ）が表示される
    And 入力欄に表示されるメモが入力した内容に更新される

  Scenario: メモを編集して保存する
    Given ウェブサイト設定の詳細画面を表示しており、既にメモが入力されている状態
    When メモの内容を変更して「保存」ボタンをクリック
    Then メモが更新されたことを示すフィードバック（成功メッセージ）が表示される
    And 入力欄に表示されるメモが新しい内容に更新される

  Scenario: メモをクリアして保存する
    Given ウェブサイト設定の詳細画面を表示しており、既にメモが入力されている状態
    When メモ入力欄を空にして「保存」ボタンをクリック
    Then メモが削除されたことを示すフィードバックが表示される
    And 入力欄に表示されるメモが空になる

  Scenario: メモ入力欄を表示する
    Given ウェブサイト設定の詳細画面を表示
    Then メモを入力するためのテキストエリア（または複数行入力フィールド）が表示される
    And 入力欄のラベルまたはプレースホルダーに「メモ」や「Notes」などのテキストが表示される
    And 1行以上の複数行入力に対応している

  Scenario: 画面再読み込み後もメモが保持される
    Given ウェブサイト設定の詳細画面でメモを入力して保存している
    When ブラウザの再読み込み（F5 または画面遷移して戻る）を実行
    Then メモが保存時の内容と同じ状態で表示される

  Scenario: メモの最大文字数制限を保存時に確認する
    Given ウェブサイト設定の詳細画面を表示
    When メモ入力欄に500文字のテキストを入力して「保存」ボタンをクリック
    Then メモが正常に保存され、フィードバック（成功メッセージ）が表示される
    And 画面再読み込み後もメモが500文字の内容で表示される

  Scenario: メモが500文字を超える場合は保存させない
    Given ウェブサイト設定の詳細画面でメモ入力欄にフォーカス
    When 501文字以上の内容を入力して「保存」ボタンをクリック
    Then 保存が実行されず、エラーメッセージ「メモは500文字以内です」が表示される
    And バリデーションエラーが発生し、ユーザーが修正を促される

  Scenario: メモのバリデーションエラー時の表示
    Given ウェブサイト設定の詳細画面
    When 無効な内容を入力して「保存」ボタンをクリック（例：501文字以上）
    Then 入力欄の周囲がエラー表示（赤い枠など）される
    And 具体的なエラーメッセージが表示される
    And 「保存」ボタンが無効化される（クリックできない状態にする）か、クリック後にエラーが返される
```

#### US-201-2: ウェブサイト一覧でメモを表示する

**ユーザーストーリー**
> サイト運用者として、ウェブサイト一覧の一覧表示画面で、各サイトに付与されたメモを確認したい。
> なぜなら、サイトの役割を素早く把握したいから。

**受け入れ条件**

```gherkin
Feature: ウェブサイト一覧でのメモ表示

  Scenario: メモが設定されているサイトを一覧で確認する
    Given ウェブサイト一覧画面を表示
    When メモが入力されているウェブサイトを表示
    Then そのサイトの行または領域にメモの内容（全文または省略形）が表示される
    And メモが無いサイトは空欄または「-」などで表示される

  Scenario: 長いメモは省略表示される
    Given ウェブサイト一覧画面を表示
    When 長いメモ（例：100文字以上）が入力されているサイトを表示
    Then メモが省略形（最初の50文字など + 「...」）で表示される
    And ツールチップ（hover時）に全文が表示される（推奨）
    または、詳細画面で全文を確認できる状態

  Scenario: メモが未入力のサイトは何も表示しない
    Given ウェブサイト一覧画面を表示
    When メモが未入力（NULL または 空文字列）のサイトを表示
    Then そのサイトの行またはメモ列には何も表示されない（空のセル）
    And エラーメッセージやプレースホルダー（「メモなし」など）は表示されない

  Scenario: 一覧表示のレイアウト
    Given ウェブサイト一覧画面を表示
    Then メモカラムがサイト名、ドメイン等の既存カラムとともに表示される
    And レイアウトが既存の一覧表示スタイルと一貫している
```

#### US-201-3: 既存のメモが未設定のウェブサイトでもエラーにならない

**ユーザーストーリー**
> サイト運用者として、メモ機能が追加される前に登録した既存のウェブサイトが、エラーなく引き続き使用できるようにしたい。
> なぜなら、機能追加によってシステムが壊れることを避けたいから。

**受け入れ条件**

```gherkin
Feature: 既存ウェブサイトの後方互換性

  Scenario: メモ機能追加前の既存サイトを表示する
    Given メモ機能が導入されるまえに登録されたウェブサイト（メモ = NULL または 空）
    When そのウェブサイトの設定詳細画面を開く
    Then エラーが発生せず、ページが正常に読み込まれる
    And メモ入力欄は空の状態で表示される

  Scenario: メモ機能追加前の既存サイトを一覧で表示する
    Given メモ機能が導入される前に登録されたウェブサイト
    When ウェブサイト一覧画面を表示
    Then エラーが発生せず、サイトが正常に表示される
    And メモ列は空（何も表示されない）
```

---

#### US-201-4: メモ編集権限のチェック

**ユーザーストーリー**
> システム管理者として、ウェブサイト管理メモが権限管理に従うようにしたい。
> なぜなら、編集権限がないユーザーによる無意識・意図的な改ざんを防ぎたいから。

**受け入れ条件**

```gherkin
Feature: メモ編集の権限チェック

  Scenario: 編集権限ありユーザーはメモを編集できる
    Given ウェブサイト設定画面に対する編集権限を持つユーザーでログイン
    When ウェブサイト設定の詳細画面を表示
    Then メモ入力欄がアクティブ（編集可能な状態）で表示される
    And 「保存」ボタンが利用可能な状態で表示される

  Scenario: 編集権限なしユーザーはメモを編集できない
    Given ウェブサイト設定画面に対する閲覧権限しかないユーザーでログイン
    When ウェブサイト設定の詳細画面を表示
    Then メモ入力欄は読み取り専用（無効化）で表示される
    And 「保存」ボタンは非表示またはクリック不可な状態で表示される

  Scenario: 無権限ユーザーがメモを更新しようとした場合
    Given ウェブサイト設定画面に対する権限がないユーザー
    When API を直接呼び出し（またはキャッシュ破棄後の画面操作）してメモを更新しようとする
    Then サーバー側でエラー（401/403）が返され、メモは更新されない
    And クライアント側でエラーメッセージが表示される
```

## 3. 非機能要件

### 3.1 データベース・永続性
- **要件**: メモはデータベースに永続化され、アプリケーション再起動後も喪失しない
- **理由**: サイト運用情報の信頼性確保

### 3.2 パフォーマンス
- **要件**: 今回フェーズではスコープ外。パフォーマンス要件は次フェーズ以降で検討する
- **理由**: MVP の機能実装を優先

### 3.3 セキュリティ
- **要件 1**: メモの編集操作時に、ウェブサイト管理権限の確認を行う
- **要件 2**: メモの内容は機密情報を含む可能性があるため、HTTPS 通信で暗号化される
- **要件 3**: メモはログ・監査対象外（ただし、監査上必要な場合は後で追加検討）
- **理由**: 不正な操作防止・データ保護

### 3.4 スケーラビリティ
- **要件**: メモフィールドの追加により、ウェブサイトテーブルのクエリパフォーマンスが著しく低下しない
- **理由**: 多数のサイト登録ユーザーでの対応

### 3.5 コード・スタイル規約への準拠
- **要件 1**: TypeScript で型安全に実装すること
- **要件 2**: Next.js App Router のルーティング・レイアウトに従うこと
- **要件 3**: Zod によるスキーマ検証を使用すること
- **要件 4**: Prisma によるデータベース操作を使用すること
- **要件 5**: UI コンポーネントは `@umami/react-zen` の既存コンポーネントまたはパターンに従うこと
- **理由**: 既存コードベースとの一貫性・保守性確保

## 4. スコープ定義

### 対象（Must Have）
- ウェブサイト設定詳細画面でのメモ入出力
- メモの永続化（DB 保存）
- ウェブサイト一覧でのメモ表示（省略表示対応）
- 最大 500 文字の制限・バリデーション
- 既存サイトの後方互換性確保
- 編集権限チェック

### 対象外（Won't Have）
- メモの履歴管理（変更前後の履歴追跡は、今フェーズでは不要）
- メモへのタグ・カテゴリー分類
- メモの全文検索機能
- メモの監査ログ（一般的な操作ログには含まれる可能性あり）
- メモのマークダウン・リッチテキスト対応（プレーンテキストのみ）

### 検討中（Should Have → 将来の拡張）
- メモ入力時の自動保存（オプション：UX 向上ため）
- 文字数カウンター表示（オプション：ユーザー利便性向上）
- メモの一括削除・エクスポート機能

## 6. 未決事項・前提・リスク

### 6.1 未決事項（要件確定時に決定必要）

| # | 項目 | 現状 | 決定者 |
|---|------|------|--------|
| 1 | メモフィールドのデータベーススキーマ（TEXT / VARCHAR など） | VARCHAR (500) に決定 | Backend Architect |
| 2 | メモ一覧表示での省略文字数（50 文字 / 100 文字など） | UI設計時に検討 | Frontend Engineer |
| 3 | メモ一覧での表示位置・レイアウト（カラム追加 / モーダル等） | UIデザインフェーズで決定 | Frontend Engineer |
| 4 | ツールチップの表示対応（hover で全文表示するか否か） | 今回フェーズではスコープ外 | Frontend Engineer |
| 5 | メモ削除時のユーザー確認（確認ダイアログ要否） | 削除時の確認は不要（メモを空にして保存で対応） | Frontend Engineer |

### 6.2 前提・制約

- Umami の既存の権限管理システムが整備されており、「ウェブサイト編集権限」が定義されていることを前提とする
- Prisma スキーマ・マイグレーションの実装は別途スケジューリング
- メモの履歴管理・削除ログは将来の要件として残す

### 6.3 リスク

| リスク | 影響 | 対策 |
|--------|------|------|
| 大量のメモテキスト（例：全ユーザー分の全サイトのメモ）をDB から一度に読み込むと、一覧表示パフォーマンス低下 | 中 | DB クエリの最適化（選択カラム絞り込み、ページネーション） |
| 既存データベース構造にメモフィールドを追加する際、既存レコードの NULL 処理が不完全だと、バージョン管理・デプロイで破損 | 中 | Prisma マイグレーションの十分なテスト・ロールバック計画 |
| 権限チェック漏れにより、権限なしユーザーがメモを編集できる脆弱性が発生 | 高 | 権限チェックのユニットテスト・E2E テストの充実、Code Review |

## 7. 受け入れ条件サマリー

本要件の実装完了時に、以下を検証する：

1. **機能面**
   - [ ] ウェブサイト設定詳細画面でメモの入力・編集・削除が可能
   - [ ] メモが DB に永続化され、画面再読み込み後も保持される
   - [ ] ウェブサイト一覧でメモが表示される（省略形対応）
   - [ ] メモが 500 文字を超える場合、保存がブロックされる
   - [ ] 既存のメモが未設定のサイトでもエラーが発生しない
   - [ ] メモ編集権限のない（閲覧権限のみ）ユーザーはメモを編集できない

2. **非機能面**
   - [ ] 実装がスタイル規約（TypeScript / Next.js / Prisma / Zod / @umami/react-zen）に従っている
   - [ ] パフォーマンス（保存・読み込み 1 秒以内）を満たしている
   - [ ] 権限チェックが実装され、不正な更新がブロックされる

3. **品質面**
   - [ ] ユニットテスト・統合テストが実装されている
   - [ ] E2E テストで実際の操作フローが検証される
   - [ ] Code Review で技術的品質が確認されている
