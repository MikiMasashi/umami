# 全体アーキテクチャ設計レビュー結果: US-201

- 対象: `docs/specifications/architecture-specification.md`（特に §4 テスト容易性の契約）
- レビュー観点: テスト容易性 / 契約の妥当性 / 実装フェーズとの整合

---

## 1. 良い点

- 新規レイヤ・エンドポイント・権限体系を導入せず、既存の取得/更新経路に `notes` を
  1 フィールド足すだけの最小構成で、退行リスクが低い。
- テスト容易性の契約を **URL / DOM / HTTP** に限定し、子コンポーネントの分割・props を
  契約から除外している。これにより「レビュー済みテストは変更しない」後続制約と、
  実装フェーズの構造自由度を両立できている。
- コンポーネントテストのエントリポイントをルート単位のページモジュールに固定し、
  MSW + ストア注入で外部境界のみを制御する方針が、脆いテストを避けている。

## 2. 指摘・懸念と対応

| # | 懸念 | 対応 / 判断 |
| --- | --- | --- |
| R-1 | 保存成功の「通知（トースト）」は jsdom で描画されず、コンポーネントテストで検証不可 | 保存成功の確証は E2E（実 Toaster）で担保。コンポーネントテストは「入力可能」「永続値の表示」「エラー非表示」を DOM で検証（AC-1 の中核＝入力・保存能力は担保） |
| R-2 | 一覧の「省略表示」の具体値が未確定（OQ-3） | 省略の長さ・全文確認手段は UI 実装時決定。契約では「`website-notes` が非空行に存在し本文を含む」までに留め、切り詰め長には依存させない（テストの過剰拘束を回避） |
| R-3 | 権限による読み取り専用表示（OQ-4）のクライアント判定はやや実装依存 | 契約は「更新権限が無い場合、`input-notes` の `textbox` は `readonly`」という DOM 観測に限定。権限そのものの正当性は E2E のサーバ 401 で担保 |
| R-4 | 設定詳細ページは多数の子パネルを描画し、コンポーネントテストが重い | MSW の寛容なデフォルトハンドラで未関係エンドポイントを吸収し、対象パネルの描画を安定化（プロトタイプで描画確認済み） |

## 3. 代替案と却下理由

- **代替1: コンポーネントテストで `WebsiteEditForm` を直接描画する。**
  却下理由: 制約「対象はルート単位のエントリポイント」に反する。子部品を直接描画すると
  実装フェーズの分割変更でテストが壊れる。
- **代替2: トースト文言までコンポーネントテストの契約に含める。**
  却下理由: jsdom で Toaster が描画されず実装後も緑にならない恐れ。E2E に委譲。
- **代替3: 一覧の省略後文字列長を契約に含める。**
  却下理由: OQ-3 未決。過剰拘束となり実装フェーズでテスト書き換えが必要になる。

## 4. 結論

アーキテクチャと契約を承認。実装フェーズは §4 の契約（ルート・セレクタ・文言・HTTP）を
満たすことでレビュー済みテストを緑化できる。
