# E2Eテスト設計 US-201

## スコープ

E2Eテストでは、Webサイトのメモ機能における重要なユーザージャーニーとAPIのガードレールを対象とする。可能な限りロール/テキストベースのセレクタを使用し、UI上で安定したフォーム/一覧のフックが必要な箇所ではレビュー済みの `data-test` 契約を使用する。

## シナリオ

| ID | シナリオ | 検証内容 |
| --- | --- | --- |
| E2E-US-201-01 | Webサイト編集ページから500文字以下のメモを保存し、再読み込みする。 | `input-notes` が表示されること、保存に成功すること、再読み込み後もテキストエリアに保存済みの値が保持されること。 |
| E2E-US-201-02 | メモがあるWebサイトにのみ一覧上の要約を表示する。 | API更新レスポンスに `notes` が含まれること、`/settings/websites` でメモがあるサイトには `website-note-summary-{websiteId}` が描画され、未設定のサイトには要約/プレースホルダーが表示されないこと。 |
| E2E-US-201-03 | UIと直接APIの両方で501文字のメモを拒否する。 | UIに `Notes must be 500 characters or fewer.` が表示されること、APIがHTTP 400と正確なバリデーションエラーを返すこと、既存のメモが変更されないこと。 |
| E2E-US-201-04 | メモをクリアし、権限のない直接更新をブロックする。 | 空のメモが `null` として永続化されること、更新権限のないユーザーによる直接更新がHTTP 401を返し、メモを上書きできないこと。 |

## レビュー補足

E2E層では、すべての描画詳細を意図的に検証対象にしない。永続化、再読み込み時の挙動、一覧での表示有無、バリデーション、認可を検証する。これらがレイヤー横断のリスクであるため。
