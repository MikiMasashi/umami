# US-201 要件定義: ウェブサイトメモ

## 1. 背景・目的

umami に登録するウェブサイトが増えると、サイト名とドメインだけでは「本番/検証用の区別」「依頼元」「運用上の補足」などを判断しづらくなる。サイト運用者が各ウェブサイトに自由記述のメモを残せるようにし、管理画面上でサイトの用途や背景を素早く把握できる状態にする。

## 2. 対象ユーザー・ステークホルダー

| 区分 | 内容 |
| --- | --- |
| 主ユーザー | umami にウェブサイトを登録・管理するサイト運用者 |
| 関連ユーザー | ウェブサイト設定を閲覧する管理者・チームメンバー |
| 利害関係 | 登録サイトの識別、引き継ぎ、運用判断を正確かつ効率的に行いたい |

## 3. 成功指標

- サイト運用者がウェブサイト編集画面で 500 文字以内のメモを入力・編集・保存できる。
- 保存済みメモがウェブサイト一覧で確認でき、再読み込み後も保持される。
- メモ未設定の既存ウェブサイトも従来どおり表示・更新できる。
- ウェブサイト更新権限を持たないユーザーはメモを変更できない。

## 4. スコープ

### 対象

- ウェブサイトに紐づく自由記述メモの保存・更新・表示。
- Settings → Websites → 対象サイトの編集画面でのメモ入力欄の追加。
- Settings → Websites の一覧上でのメモ表示。
- 500 文字程度を上限とする入力・保存時のバリデーション。
- 既存ウェブサイトでメモが未設定の場合の後方互換対応。
- 既存の権限モデルに沿ったメモ更新制御。

### 対象外

- メモの履歴管理、変更者・変更日時の監査ログ追加。
- メモ本文の検索、フィルタ、ソート機能。
- メモのリッチテキスト化、Markdown プレビュー、添付ファイル対応。
- ウェブサイト以外のエンティティへのメモ機能追加。
- 既存サイト名・ドメイン・チーム権限モデルの仕様変更。

## 5. ユーザーストーリー

### US-201

サイト運用者として、登録している各ウェブサイトにメモを書き残したい。なぜなら、ウェブサイトが増えたときに、名前とドメインだけでは本番/検証用の区別や依頼元などの運用背景が分からなくなるため。

## 6. 機能要件

| ID | 要件 | 優先度 | 根拠 |
| --- | --- | --- | --- |
| FR-201-01 | ウェブサイト編集画面に、対象ウェブサイトのメモを入力・編集できる自由記述欄を表示する。 | Must | サイトごとに運用メモを管理するため。 |
| FR-201-02 | メモ保存時、対象ウェブサイトにメモを永続化する。 | Must | 再読み込み後もメモを参照できる必要があるため。 |
| FR-201-03 | 保存済みメモをウェブサイト編集画面の初期値として表示する。 | Must | 既存メモを確認・修正できる必要があるため。 |
| FR-201-04 | ウェブサイト一覧に、メモが設定されているサイトのみメモ内容を表示する。 | Must | 一覧上でサイトの補足情報を把握したいため。 |
| FR-201-05 | ウェブサイト一覧では、長いメモを省略表示してよい。ただしメモが存在することと概要が分かる表示にする。 | Should | 一覧の可読性を損なわずに補足情報を示すため。 |
| FR-201-06 | メモが未入力または空のサイトでは、一覧上にメモ表示領域またはメモ本文を出さない。 | Must | メモ未設定サイトの画面ノイズを増やさないため。 |
| FR-201-07 | メモは最大 500 文字まで保存可能とし、上限を超える場合は保存を拒否してユーザーに分かる形でエラーを示す。 | Must | 過度に長い入力による UI・DB・運用上の負荷を防ぐため。 |
| FR-201-08 | 既存のウェブサイトでメモが未設定でも、一覧表示・詳細表示・更新処理がエラーにならない。 | Must | 既存データとの後方互換性を維持するため。 |
| FR-201-09 | ウェブサイト更新権限を持たないユーザーは、メモを新規保存・変更・削除できない。 | Must | メモもウェブサイト設定情報の一部として保護する必要があるため。 |
| FR-201-10 | メモの保存先、フィールド名、API 入出力、バリデーション、UI コンポーネントは既存の TypeScript・Next.js App Router・zod・Prisma・`@umami/react-zen` の実装スタイルに合わせる。 | Should | 既存保守性と実装一貫性を保つため。 |

## 7. 非機能要件

| ID | 分類 | 要件 | 優先度 |
| --- | --- | --- | --- |
| NFR-201-01 | 互換性 | メモ未設定の既存レコードを扱う画面・API は、追加項目が存在しないまたは null/空の場合でも従来どおり動作する。 | Must |
| NFR-201-02 | セキュリティ | メモ更新は既存のウェブサイト更新権限チェックを通過した場合のみ許可する。クライアント側の表示制御だけに依存しない。 | Must |
| NFR-201-03 | 入力検証 | 500 文字上限はクライアント側だけでなく、保存処理側でも検証する。 | Must |
| NFR-201-04 | 可用性 | メモの有無によってウェブサイト一覧・編集画面の読み込みが失敗しない。 | Must |
| NFR-201-05 | 性能 | ウェブサイト一覧にメモを表示しても、通常の一覧表示体験を著しく悪化させない。不要に追加リクエストを増やさないことが望ましい。 | Should |
| NFR-201-06 | UX | 文字数超過時は保存失敗の理由がユーザーに分かるメッセージまたは既存フォームのエラー表現で通知される。 | Should |
| NFR-201-07 | 保守性 | 既存の型定義、スキーマ、フォーム、API の責務分離に従い、メモ項目だけが特別扱いにならないようにする。 | Should |

## 8. 受け入れ条件

### AC-201-01: 編集画面でメモを保存できる

- Given ウェブサイト更新権限を持つサイト運用者が Settings → Websites → 対象サイトの編集画面を開いている
- When 500 文字以内のメモを入力して保存する
- Then 保存が成功し、同じ編集画面を再度開いたときに保存したメモが表示される

### AC-201-02: 保存したメモは再読み込み後も残る

- Given ウェブサイトにメモが保存されている
- When ブラウザを再読み込みする、または一度別画面に移動してから対象サイトの編集画面を開く
- Then 保存済みメモが失われずに表示される

### AC-201-03: ウェブサイト一覧でメモを確認できる

- Given メモが設定されたウェブサイトが存在する
- When Settings → Websites の一覧を表示する
- Then 対象サイトの行またはカード上でメモ内容または省略されたメモ内容を確認できる

### AC-201-04: メモ未入力のサイトでは一覧にメモを表示しない

- Given メモが未入力のウェブサイトが存在する
- When Settings → Websites の一覧を表示する
- Then 対象サイトにはメモ本文が表示されない

### AC-201-05: 500 文字を超えるメモは保存できない

- Given ウェブサイト更新権限を持つサイト運用者がウェブサイト編集画面を開いている
- When 500 文字を超えるメモを入力して保存する
- Then 保存は拒否され、文字数上限を超えていることがユーザーに分かる
- And 既存の保存済みメモがある場合、その内容は不正な入力で上書きされない

### AC-201-06: 既存ウェブサイトはメモ未設定でも従来どおり動作する

- Given メモが未設定の既存ウェブサイトが存在する
- When ウェブサイト一覧を表示する、または対象サイトの編集画面を開く
- Then エラーにならず、既存のサイト名・ドメイン等の情報を従来どおり確認・更新できる

### AC-201-07: 権限のないユーザーはメモを変更できない

- Given ウェブサイト更新権限を持たないユーザーが対象ウェブサイトにアクセスできる
- When メモを新規保存、編集、または削除しようとする
- Then メモは変更されず、権限がない操作として拒否される

### AC-201-08: 空のメモを保存できる

- Given ウェブサイトに既存メモが保存されている
- When ウェブサイト更新権限を持つサイト運用者がメモ欄を空にして保存する
- Then 保存が成功し、以後そのサイトはメモ未入力として扱われる
- And ウェブサイト一覧にはメモ本文が表示されない

## 9. MVP 定義

MVP は、ウェブサイト編集画面で 500 文字以内のメモを保存・再表示でき、ウェブサイト一覧でメモ設定済みサイトのメモを確認でき、メモ未設定の既存サイトと権限チェックが正しく扱われる状態とする。検索・履歴・リッチテキストなどの拡張機能は MVP に含めない。

## 10. 前提・制約

- メモはウェブサイト設定情報の一部として扱い、ウェブサイト更新権限と同じ権限境界で保護する。
- メモの最大長は「500 文字」とする。ここでの文字数はアプリケーション既存の文字列長検証の単位に従う。
- UI 文言・配置は既存画面のデザイン、フォーム表現、エラー表示パターンに合わせる。
- メモ未設定状態は null、空文字、未定義のいずれで実装されてもよいが、ユーザー体験としては「メモなし」として一貫して扱う。

## 11. リスク・確認事項

| 種別 | 内容 | 対応方針 |
| --- | --- | --- |
| 確認事項 | 一覧での省略文字数・表示形式は未指定。 | 既存一覧 UI の幅とスタイルに合わせ、省略表示でもメモの概要が分かることを要件とする。 |
| 確認事項 | メモの DB フィールド名や null/空文字の扱いは未指定。 | 既存 Prisma スキーマと API スタイルに合わせる。要件上はメモ未設定として一貫表示できればよい。 |
| リスク | メモ項目の追加により既存 API レスポンスや一覧取得処理の型・移行に影響が出る可能性がある。 | 既存ウェブサイトの後方互換を Must とし、未設定データでの表示・更新を受け入れ条件に含める。 |
| リスク | クライアント側だけで文字数・権限を制御すると不正更新が可能になる。 | サーバー側の入力検証と権限チェックを Must として明記する。 |

## 12. 抜け漏れ・矛盾チェック

- 課題、対象ユーザー、成功指標を明文化済み。
- 機能要件は入力・保存・再表示・一覧表示・未入力時・文字数上限・権限・既存データ互換を網羅。
- 非機能要件は互換性、セキュリティ、入力検証、可用性、性能、UX、保守性を確認済み。
- スコープ外として履歴、検索、リッチテキスト、添付、他エンティティ対応を明示済み。
- 受け入れ条件は Given/When/Then 形式で検証可能な粒度に整理済み。
- 現時点で実装を妨げる矛盾はない。未指定事項は前提または確認事項として整理済み。
