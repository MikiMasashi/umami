# US-201 要件定義書：ウェブサイトへのメモ機能

## 1. 背景・目的

### 課題
umami に登録したウェブサイト数が増えてくると、以下の情報が名前とドメインだけでは不足する：
- 本番環境か検証用か
- 誰の依頼で登録されたのか
- 関連する補足情報

その結果、サイト運用者が正確な情報を得られず、ウェブサイト管理の効率性が低下している。

### 目的
ウェブサイトレコードに**自由記述のメモ機能**を追加することで、運用者が各サイトの補足情報を記録・参照でき、ウェブサイト管理の効率性と運用性を向上させる。

### 成功指標
- ウェブサイト詳細設定画面でメモの入力・編集・保存ができる
- 保存したメモは永続化され、画面リロード後も保持される
- ウェブサイト一覧でメモの有無と内容（省略表示）が確認できる
- 既存のメモなしウェブサイトが引き続き正常に動作する

## 2. ユーザーストーリー・受け入れ条件

### US-201-1：ウェブサイト詳細設定画面でメモを入力・保存する

**ユーザーストーリー：**
```
サイト運用者として、ウェブサイトの詳細設定画面からメモを入力・編集・保存したい。
そうすることで、ウェブサイトにまつわる補足情報（本番/検証用、依頼元など）を
記録しておくことができ、後で確認するときに役立つ。
```

**受け入れ条件：**

| # | Given（前提条件）| When（操作） | Then（期待結果）|
|---|---|---|---|
| 1-1 | ウェブサイト詳細設定画面が表示されている | メモ入力フィールドに500文字以内のテキストを入力し、「保存」ボタンをクリック | メモが保存され、画面上に確認メッセージが表示される |
| 1-2 | メモが既に保存されている | メモ入力フィールドを編集し、「保存」ボタンをクリック | 新しいメモが保存される |
| 1-3 | メモ入力フィールドに500文字を超えるテキストが入力されている | 「保存」ボタンをクリック | 保存が拒否され、「500文字以内で入力してください」というエラーメッセージが表示される |
| 1-4 | メモ入力フィールドが空の状態 | 「保存」ボタンをクリック | メモが空（NULL）として保存される |
| 1-5 | メモが保存された | ページをリロード（F5キーなど） | 保存したメモが表示される |

---

### US-201-2：ウェブサイト一覧でメモを確認する

**ユーザーストーリー：**
```
サイト運用者として、ウェブサイト一覧にメモが表示されたい。
そうすることで、詳細設定画面を開かなくても各サイトの概要が把握でき、
効率的にウェブサイトを検索・管理できる。
```

**受け入れ条件：**

| # | Given（前提条件） | When（操作） | Then（期待結果） |
|---|---|---|---|
| 2-1 | ウェブサイト一覧が表示されている、かつ複数のサイトにメモが設定されている | 一覧を表示 | メモが設定されているサイトについて、各行にメモ内容が表示される |
| 2-2 | ウェブサイト一覧が表示されている、かつメモが100文字以上ある | 一覧を表示 | メモが省略表示される（例：最初の100文字 + "..." ） |
| 2-3 | メモが未設定のウェブサイト | 一覧を表示 | メモ列は空白またはメモなしを示す表示（例："-"）となる |
| 2-4 | ウェブサイト一覧でメモを確認し、詳細設定画面を開く | 詳細設定画面でメモを確認 | 一覧に表示されていたメモと詳細設定画面のメモが同じ内容である |

---

### US-201-3：メモの変更権限を制御する

**ユーザーストーリー：**
```
Umami の管理者として、ウェブサイトの設定変更権限がないユーザーがメモを
勝手に変更できないようにしたい。
そうすることで、ウェブサイト設定の一貫性と信頼性を保つことができる。
```

**受け入れ条件：**

| # | Given（前提条件） | When（操作） | Then（期待結果） |
|---|---|---|---|
| 3-1 | ウェブサイト詳細設定画面を開く権限がないユーザーが、詳細設定ページにアクセス | ページにアクセス | 403 Forbidden またはリダイレクトエラーが表示される |
| 3-2 | ウェブサイト設定変更権限のないユーザーが、メモ更新 API を直接呼び出し | API 呼び出し | 403 Forbidden または権限エラーレスポンス（HTTP 403/401）が返される |
| 3-3 | ウェブサイト設定変更権限のあるユーザーがメモを入力・保存 | メモを保存 | メモが正常に保存される |

---

### US-201-4：既存のメモなしウェブサイトの互換性

**ユーザーストーリー：**
```
サイト管理者として、本機能実装前から登録されているウェブサイト（メモが設定されていない）が、
実装後も引き続き正常に動作し、エラーが発生しないようにしたい。
そうすることで、既存ユーザーが混乱せず、スムーズに機能を利用できる。
```

**受け入れ条件：**

| # | Given（前提条件） | When（操作） | Then（期待結果） |
|---|---|---|---|
| 4-1 | メモが未設定のウェブサイトが存在する | ウェブサイト一覧を表示 | エラーが発生せず、当該サイトが通常通り表示される |
| 4-2 | メモが NULL のウェブサイト | 詳細設定画面を開く | エラーが発生せず、メモ入力フィールドは空（NULL）として表示される |
| 4-3 | メモなしウェブサイト | データベースクエリを実行 | メモ フィールドは NULL として扱われる |

## 3. 機能要件・非機能要件

### 3.1 機能要件（MoSCoW）

| 優先度 | 要件ID | 要件 | 説明 |
|---|---|---|---|
| **MUST** | FR-1 | メモの入力・編集・保存 | ウェブサイト詳細設定画面（Settings → Websites → [サイト名] → 編集）でメモを入力・編集・保存できる |
| **MUST** | FR-2 | メモの永続化 | 保存したメモはデータベースに格納され、ページリロード後も保持される |
| **MUST** | FR-3 | メモの文字数上限制御 | 500文字以内のメモのみ保存可能。超過時は保存を拒否しエラーメッセージを表示 |
| **MUST** | FR-4 | ウェブサイト一覧でのメモ表示 | ウェブサイト一覧にメモ列を追加し、メモが設定されているサイトについて内容を表示。長い場合は省略表示（例：最初の100文字 + "..."） |
| **MUST** | FR-5 | 既存サイトの互換性 | メモが未設定のウェブサイトでもエラーなく正常に動作する（バックワード互換性） |
| **MUST** | FR-6 | メモ変更時の権限チェック | ウェブサイト設定変更権限のないユーザーはメモを変更できない。権限ない場合は API 呼び出し時に 403 を返す |
| **SHOULD** | FR-7 | メモのクリア機能 | 入力済みのメモを削除（クリア）できる機能 |
| **COULD** | FR-8 | メモの検索・フィルター | ウェブサイト一覧でメモの内容で検索・フィルターできる（将来検討） |
| **WON'T** | FR-9 | メモのバージョン管理・履歴 | 本機能スコープ外。メモの更新履歴は記録しない |
| **WON'T** | FR-10 | メモのマークダウン対応 | 本機能スコープ外。プレーンテキストのみ |

### 3.2 非機能要件

| 分類 | 要件ID | 要件 | 説明 |
|---|---|---|---|
| **セキュリティ** | NFR-1 | 権限チェック | ウェブサイト設定変更権限がないユーザーによるメモ変更を防ぐ。既存の権限チェック機構（Umami の RBAC）を流用 |
| **セキュリティ** | NFR-2 | データ検証 | ユーザー入力は zod でバリデーション（文字数上限 500 字など）。SQL インジェクション対策は Prisma ORM で対応 |
| **セキュリティ** | NFR-3 | XSS 対策 | メモ表示時は自動エスケープ。Next.js 標準機能で対応 |
| **パフォーマンス** | NFR-4 | クエリ最適化 | ウェブサイト一覧取得時、メモカラムの追加が既存のクエリパフォーマンスに悪影響を与えないこと |
| **ユーザビリティ** | NFR-5 | メモ入力フィールドのサイズ | テキストエリアの高さは適切に設定（例：5-10行分）し、運用者が入力しやすい UI に |
| **互換性** | NFR-6 | バックワード互換性 | メモ未設定のウェブサイトが引き続き正常に機能すること。既存コードへの影響を最小化 |
| **保守性** | NFR-7 | コードスタイル | TypeScript・Next.js App Router・zod・Prisma・@umami/react-zen に従い、既存実装と統一されたスタイル |
| **アクセシビリティ** | NFR-8 | フォームアクセシビリティ | メモ入力フィールドに適切な label、ARIA 属性を付与し、スクリーン リーダー対応 |

## 4. スコープ

### 4.1 対象（In Scope）

- ✅ ウェブサイトに「メモ」フィールドを追加（Prisma スキーマ + DB マイグレーション）
- ✅ ウェブサイト詳細設定画面でメモを入力・編集・保存
- ✅ ウェブサイト一覧でメモを表示（省略表示含む）
- ✅ 文字数上限チェック（500文字）と UI での検証フィードバック
- ✅ 既存のメモなしウェブサイトの互換性
- ✅ メモ変更時の権限チェック（既存の権限チェック機構を利用）
- ✅ 既存実装スタイル（TypeScript・Next.js App Router・zod・Prisma・@umami/react-zen）への適合

### 4.2 対象外（Out of Scope）

- ❌ メモの更新履歴・バージョン管理（本機能では不要）
- ❌ メモ内容での検索・フィルター機能（将来検討）
- ❌ マークダウン形式でのメモ記述（プレーンテキストのみ）
- ❌ メモのタグ付け・カテゴリー分類
- ❌ 他のユーザー/チームとのメモ共有機能
- ❌ メモ作成者・更新日時の自動記録（本機能では不要）
- ❌ UI ローカライゼーション（Umami の既存方針に従う）

## 5. 影響分析・依存関係

### 5.1 既存機能への影響
- **ウェブサイト管理画面**: メモ列の追加に伴い、画面レイアウト調整が必要
- **Prisma スキーマ**: Website モデルにメモフィールドを追加
- **ウェブサイト API**: GET/POST/UPDATE エンドポイントにメモサポートを追加

### 5.2 前提・依存事項
- ウェブサイトの詳細設定画面がすでに存在し、編集機能があること
- Prisma ORM を使用したデータベースアクセス層が存在すること
- 既存の権限チェック機構（ウェブサイト設定変更権限）が存在すること

### 5.3 後続作業への影響
- テスト実装時、メモのバリデーション・権限チェック・互換性を含む E2E テストが必要
- UI テストでは、メモ入力フィールド・エラーメッセージ・省略表示の表現を検証

## 6. 抜け漏れチェック・疑問点

### 6.1 確認済みの要件
✅ メモの入力・編集・保存  
✅ 永続化  
✅ 一覧での表示  
✅ 文字数上限  
✅ 既存サイト互換性  
✅ 権限チェック  
✅ 実装スタイル指定  

### 6.2 設計時に確認・決定が必要な事項

| # | 項目 | 説明 | 状態 |
|---|---|---|---|
| Q-1 | メモ列の表示位置 | ウェブサイト一覧でメモ列をどこに配置するか（名前の隣か、最後か） | **要確認** |
| Q-2 | 省略表示の文字数 | 一覧でメモを省略表示する際、何文字まで表示するか（100文字？） | **要確認** |
| Q-3 | 省略表示のインジケーター | 省略時のインジケーター表現（"..." か、"他 N 文字" か） | **要確認** |
| Q-4 | メモクリアの UI | 既存のメモを削除する UI（「クリア」ボタンか、フィールドを空にして保存か） | **要確認** |
| Q-5 | エラーメッセージの文言 | UI に表示するエラーメッセージの正確な文言と言語 | **要確認** |
| Q-6 | メモフィールドの型制約 | DB 側でメモを VARCHAR か TEXT か（500文字上限に対してどの型が最適か） | **要確認** |
| Q-7 | トリミング処理 | ユーザー入力の前後の空白をトリミングするか | **要確認** |
| Q-8 | 複数行テキスト対応 | メモ入力時、改行は許可するか | **デフォルト：許可** |

### 6.3 既知の制限・リスク

| # | リスク | 影響度 | 対応策 |
|---|---|---|---|
| R-1 | ウェブサイト一覧表示のパフォーマンス低下 | 中 | Prisma クエリを最適化し、不要なメモフィールド取得を回避 |
| R-2 | 既存データベースマイグレーション | 中 | Prisma マイグレーション実施前にバックアップを推奨。NULL デフォルト値で既存レコードをカバー |
| R-3 | UI レイアウト崩れ | 低 | 長いメモ内容で既存列が圧迫されないよう、CSS ですべての列に最大幅を設定 |

## 7. MVP（Minimum Viable Product）定義

本フェーズで実装する最小限の成立条件：

- ✅ Prisma スキーマにメモフィールド追加（VARCHAR(500)）
- ✅ ウェブサイト詳細設定画面でメモの入力・編集・保存
- ✅ ウェブサイト一覧でメモの有無と内容（省略表示）を表示
- ✅ 500文字上限チェック と UI フィードバック
- ✅ 既存サイトの互換性確保
- ✅ メモ変更時の権限チェック
