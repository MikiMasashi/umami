# 要件定義書 US-201: ウェブサイトへのメモ（notes）機能

## 1. 背景・目的

### 背景
サイト運用者が umami に多数のウェブサイトを登録して運用していくと、サイト名とドメインだけでは
「どれが本番でどれが検証用か」「誰の依頼で作成したサイトか」といった管理上重要な情報が判別できなくなる。

### 課題
- 対象ユーザー: umami にウェブサイトを登録・管理するサイト運用者（ウェブサイトの更新権限を持つユーザー）。
- 課題: 名前・ドメインのみでは、サイトの用途や背景を思い出せず、運用ミス（例: 検証用サイトを本番と誤認する）につながる。

### 目的・価値
各ウェブサイトに自由記述のメモを持たせることで、運用者が用途・背景・依頼元などの補足情報を
記録・参照できるようにし、サイト管理の誤り・迷いを減らす。

### 成功指標
- ウェブサイト編集画面でメモを入力・保存・再表示でき、内容が失われない。
- ウェブサイト一覧で、メモの有無・概要が一目で分かる。
- 権限のないユーザーによるメモの改ざんが発生しない。
- 既存ウェブサイト（メモ未設定）が本機能導入後も従来どおり動作する（後方互換性の破壊がない）。

## 2. ステークホルダー / ユーザー

| 役割 | 目的（ジョブ） |
|---|---|
| サイト運用者（更新権限あり） | ウェブサイトにメモを書き残し、後で参照して管理判断に役立てたい |
| 閲覧のみのユーザー（更新権限なし） | メモを閲覧できてもよいが、書き換えはできてはならない |
| 開発者・保守担当 | 既存実装スタイル（TypeScript / Next.js App Router / zod / Prisma / `@umami/react-zen`）に沿った一貫性のある実装を維持したい |

## 3. 用語定義

- **メモ（notes）**: ウェブサイトに紐づく自由記述のテキスト情報。サイトの用途・背景・依頼元などをサイト運用者が記録するためのフィールド。
- **ウェブサイト設定の詳細画面**: `Settings → Websites → 対象サイトの編集画面`（`WebsiteEditForm` 相当の画面）。
- **ウェブサイト一覧**: 登録済みウェブサイトを一覧表示する画面（`WebsitesTable` / `WebsitesDataTable` 相当）。

## 4. スコープ

### 対象（Must / Should に対応する範囲）
- ウェブサイトエンティティに「メモ（notes）」フィールドを追加する（DB・API・UI の一連の対応）。
- ウェブサイト設定の詳細画面で、メモの入力・編集・保存ができる。
- 保存したメモは永続化され、画面再読み込み後も保持される。
- ウェブサイト一覧画面で、メモが設定されているサイトについてメモの概要（省略表示可）を表示する。メモ未設定のサイトには何も表示しない。
- メモの文字数上限（500文字程度）を設け、上限超過時は保存を拒否する。
- 既存ウェブサイト（メモ未設定 = `null`）に対して、本機能導入後もエラーなく従来どおり動作する。
- ウェブサイトの更新権限を持たないユーザーはメモを更新できない（既存の権限モデルに準拠）。

### 対象外（Won't）
- メモの変更履歴・監査ログ機能。
- メモに対するリッチテキスト（Markdown・HTML装飾等）や添付ファイルのサポート（プレーンテキストのみ）。
- メモの全文検索・フィルタ機能（一覧の絞り込み条件としての利用は本ストーリーでは対象外）。
- メモ内容の多言語翻訳・自動生成。
- チーム内でのメモごとの個別権限設定（メモの権限はウェブサイト更新権限に準拠し、メモ専用の権限区分は設けない）。
- メモ内容そのものに対するバリデーション（禁止語句チェック等）。文字数上限以外の内容検証は行わない。

## 5. 機能要件（ユーザーストーリー・受け入れ条件）

### US-201-1: メモの入力・編集・保存
**ユーザーストーリー**
サイト運用者として、ウェブサイト設定の詳細画面でメモを入力・編集・保存したい。
なぜなら、サイトの用途や背景を後から参照できるようにしたいから。

**受け入れ条件（Given/When/Then）**
1. Given ウェブサイトの更新権限を持つユーザーが対象サイトの設定詳細画面を開いている
   When メモ欄に任意のテキストを入力して保存する
   Then メモが保存され、成功のフィードバック（保存完了の通知）が表示される。
2. Given メモが既に設定されているサイトの設定詳細画面を開いている
   When 画面を表示する
   Then 既存のメモ内容が入力欄に表示される。
3. Given メモを編集して保存した
   When 画面をリロードする
   Then 保存した最新のメモ内容が表示される（永続化されている）。
4. Given メモ入力欄を空にして保存した
   When 保存が成功する
   Then メモは「未設定」の状態として保存される（一覧表示等でエラーにならない）。

### US-201-2: 既存ウェブサイトとの後方互換性
**ユーザーストーリー**
サイト運用者として、メモ機能導入前から存在する既存のウェブサイト（メモ未設定）についても、
これまでどおり問題なく閲覧・編集・一覧表示できるようにしたい。
なぜなら、既存運用に支障が出ないことが前提だから。

**受け入れ条件**
1. Given メモ機能導入前に作成された既存ウェブサイト（メモ未設定＝`null`相当）が存在する
   When 設定詳細画面を開く
   Then エラーにならず、メモ欄は空の状態で表示される。
2. Given 既存ウェブサイト（メモ未設定）が一覧に表示されている
   When 一覧を表示する
   Then メモ関連の表示によってエラーが発生せず、当該行にはメモの表示が何も出ない。
3. Given 既存ウェブサイト（メモ未設定）に対して、メモ以外の項目（名前・ドメイン等）のみを更新する
   When 保存する
   Then 従来どおり更新が成功し、メモは未設定のまま維持される。

### US-201-3: ウェブサイト一覧でのメモ表示
**ユーザーストーリー**
サイト運用者として、ウェブサイト一覧を見ただけで、各サイトにどんなメモが付いているか把握したい。
なぜなら、一覧から目的のサイトを素早く見分けたいから。

**受け入れ条件**
1. Given メモが設定されているウェブサイトが一覧に含まれる
   When 一覧を表示する
   Then そのサイトの行にメモの内容（または概要）が表示される。
2. Given メモの内容が一覧表示に収まらないほど長い
   When 一覧を表示する
   Then メモは省略表示される（全文表示は必須としない）。
3. Given メモが未設定のウェブサイトが一覧に含まれる
   When 一覧を表示する
   Then そのサイトの行にはメモに関する表示が何も出ない（プレースホルダー文言等も表示しない）。

### US-201-4: メモの文字数上限
**ユーザーストーリー**
サイト運用者として、メモが際限なく長くならないようにしてほしい。
なぜなら、メモは補足情報であり、長大なテキストは一覧表示や運用の妨げになるから。

**受け入れ条件**
1. Given メモ入力欄に500文字以内のテキストを入力した
   When 保存する
   Then 保存に成功する。
2. Given メモ入力欄に500文字を超えるテキストを入力した
   When 保存を実行する
   Then 保存は拒否され、エラー（バリデーションメッセージ）が表示され、メモは更新されない。
3. Given サーバー側API（POST /websites/{websiteId}相当）に500文字を超えるnotesを直接送信した
   When リクエストを処理する
   Then サーバー側でもバリデーションエラーとして拒否される（クライアント側バリデーションのみに依存しない）。

### US-201-5: 更新権限のないユーザーによる改ざん防止
**ユーザーストーリー**
サイト管理者として、ウェブサイトの更新権限を持たないユーザーがメモを書き換えられないようにしたい。
なぜなら、メモも含めたウェブサイト情報の整合性を守る必要があるから。

**受け入れ条件**
1. Given ウェブサイトの更新権限を持たないユーザーがログインしている
   When 対象ウェブサイトのメモを含む更新APIを直接呼び出す
   Then 更新は拒否され（unauthorized相当のレスポンス）、メモは変更されない。
2. Given ウェブサイトの更新権限を持たないユーザーが設定詳細画面にアクセスできる場合（閲覧権限のみ）
   When 画面を表示する
   Then メモは閲覧できるが、編集・保存操作は行えない（既存の権限モデルに準拠したUI制御）。
3. Given 既存の`canUpdateWebsite`権限チェックの仕組みがある
   When メモの更新を伴うリクエストを処理する
   Then メモの更新も既存の権限チェック（`canUpdateWebsite`）の対象に含まれる（メモ専用の別権限は設けない）。

## 6. 非機能要件

| 分類 | 要件 | 優先度 |
|---|---|---|
| データ整合性 | メモは既存ウェブサイトに対して `null`（未設定）を許容し、既存データ・既存APIレスポンスとの後方互換性を壊さない | Must |
| セキュリティ・権限 | メモの更新は既存の `canUpdateWebsite` 権限チェックの対象とし、閲覧は既存の閲覧権限（`canViewSharedWebsite`等）に準拠する | Must |
| バリデーション | メモの文字数上限（500文字程度）はクライアント側・サーバー側の両方で検証する | Must |
| 一貫性 | 実装は既存のアーキテクチャ（TypeScript, Next.js App Router, zod, Prisma, `@umami/react-zen`）のスタイルに準拠する | Must |
| 保守性 | 既存の `Website` モデル・API・フォームの構造を踏襲し、命名規則やフィールド追加の作法（`@map`等）に合わせる | Should |
| ユーザビリティ | 一覧表示でのメモ省略表示は既存の一覧UIコンポーネントの表示パターン（例: 既存の省略表示・ツールチップ等）に合わせる | Should |
| 可用性 | メモ機能追加によって既存のウェブサイト一覧・詳細取得APIのレスポンス時間に有意な劣化を生じさせない | Should |

## 7. 優先度（MoSCoW）

- **Must**: US-201-1（入力・編集・保存）, US-201-2（後方互換性）, US-201-4（文字数上限）, US-201-5（権限保護）
- **Should**: US-201-3（一覧でのメモ表示・省略表示）
- **Could**: 一覧でのメモのツールチップ全文表示、メモ表示のスタイル調整
- **Won't**: 変更履歴、リッチテキスト・添付、全文検索、多言語対応、メモ専用の権限区分

## 8. MVP定義

MVP（最小実用製品）は以下を満たすものとする:
- ウェブサイト設定詳細画面でメモの入力・編集・保存ができる（US-201-1）。
- 保存したメモが永続化され、既存ウェブサイトに影響を与えない（US-201-2）。
- 500文字の上限バリデーションがクライアント・サーバー双方に存在する（US-201-4）。
- 更新権限のないユーザーがメモを書き換えられない（US-201-5）。
- 一覧でのメモ表示（US-201-3）は Should 扱いだが、要望に明記された機能であるため初回リリースに含めることを推奨する。

## 10. 未決事項・前提・リスク（オープンクエスチョン）

1. **一覧での表示桁数・省略ルール**: 「長い場合は省略表示でよい」とのことだが、具体的な省略文字数やUIコンポーネント（ツールチップの有無等）は要望に明記されていない。
   → 前提: 既存の一覧UIコンポーネントの一般的な省略表示パターン（例: `text-overflow: ellipsis` 等）を踏襲する方針とし、詳細は設計フェーズで決定する。
2. **文字数上限の厳密値**: 要望では「500文字程度」とやや曖昧な表現。
   → 前提: 本書では上限を500文字（`max(500)`）として確定する。変更が必要な場合は別途合意が必要。
3. **メモのフィールド名・DBカラム名**: 要望では保存先やフィールド名は実装スタイルに合わせるとされている。
   → 前提: フィールド名は `notes`（Prismaモデル上は `@map("notes")` 等、既存の命名規則に準拠）とする想定。最終的な物理名は設計・実装フェーズで決定する。
4. **既存の共有（Share）画面や公開ダッシュボードでのメモ扱い**: 要望に明記がないため、メモは内部管理用情報として扱い、外部共有ページ（`/share/[slug]`）には表示しない前提とする。この前提に異論がある場合は確認が必要。
5. **チーム管理サイトでのメモ表示**: `TeamWebsitesTable` のようなチーム経由のウェブサイト一覧でもメモ表示を行うかは要望に明記がない。
   → 前提: 本ストーリーの対象は「ウェブサイト一覧」（`WebsitesTable`/`WebsitesDataTable`）とし、チーム管理画面等への展開は本ストーリーのスコープ外（将来検討）とする。
