# 要件定義書 US-201: ウェブサイトへのメモ（notes）機能

## 1. 背景・目的

サイト運用者が umami に登録した各ウェブサイトの用途（本番/検証用、依頼者など）を、名前とドメインだけでは判別できない。
そこで、各ウェブサイトに自由記述の「メモ（notes）」を持たせ、設定画面での編集と一覧画面での確認を可能にする。

## 2. スコープ

### 対象（In Scope）

- ウェブサイトごとに自由記述のメモ（notes）を1件保持できるようにする。
- ウェブサイト設定の詳細画面（Settings → Websites → 対象サイトの編集画面）でメモの入力・編集・保存ができる。
- 保存したメモは永続化され、画面再読み込み後も保持される。
- ウェブサイト一覧画面で、メモが設定されている場合はその内容（省略表示可）を表示する。メモが未設定の場合は何も表示しない。
- メモの文字数上限（500文字程度）を設け、上限超過時は保存できないようにする（サーバー側・クライアント側双方でのバリデーションを想定）。
- 既存ウェブサイト（メモ未設定＝null/空）についてもエラーなく従来通り動作すること（後方互換性）。
- ウェブサイトを更新する権限を持たないユーザーはメモを編集・保存できないこと（既存の更新権限モデルに従う）。

### 対象外（Out of Scope）

- メモの編集履歴・バージョン管理。
- メモに対するコメント・共同編集・リアルタイム同期。
- メモの全文検索・フィルタリング機能（一覧画面での検索対象への追加は本要件に含まない）。
- メモのMarkdown等リッチテキスト対応（プレーンテキストのみを想定）。
- 共有リンク（Share）経由の閲覧者に対するメモの公開/非公開制御の詳細仕様（既存の閲覧権限モデルをそのまま適用する）。
- メモに関する通知・監査ログ機能。

## 3. 機能要件（FR）

| ID | 要件 |
|----|------|
| FR-1 | ウェブサイトデータモデルに、任意入力・null許容の `notes`（メモ）フィールドを追加する。 |
| FR-2 | ウェブサイト設定の編集画面（`WebsiteEditForm` 相当）に、メモを入力・編集するためのテキスト入力欄（複数行）を追加する。 |
| FR-3 | メモはウェブサイト更新API（`POST /api/websites/{websiteId}` 相当）を通じて他の設定項目と同様に保存できる。 |
| FR-4 | 保存されたメモは永続化され、ページ再読み込み後も表示・編集画面に反映される。 |
| FR-5 | ウェブサイト一覧画面（`WebsitesTable`/`WebsitesDataTable` 相当）で、メモが設定されているウェブサイトについてはメモの内容を表示する。長い場合は省略表示（例: 末尾を省略記号で切り詰め、ホバー等で全文確認可能とする）とする。 |
| FR-6 | メモが未入力（null または空文字）のウェブサイトについては、一覧画面に何も表示しない（プレースホルダーやダミー文言を出さない）。 |
| FR-7 | メモの入力は最大500文字までとし、クライアント側フォームでも上限を明示・制限する（例: 文字数カウンタ、`maxLength`）。 |
| FR-8 | サーバー側APIでもメモの文字数上限（500文字）をバリデーションし、超過時は保存を拒否してエラーを返す。 |
| FR-9 | メモ未設定の既存ウェブサイトに対する取得・更新・一覧表示など既存操作は、エラーを発生させず従来通り動作する。 |
| FR-10 | ウェブサイトの更新権限（既存の `canUpdateWebsite` 相当の権限判定）を持たないユーザーは、メモの編集・保存操作を実行できない（APIレベルで拒否する）。 |

## 4. 非機能要件（NFR）

| ID | 要件 |
|----|------|
| NFR-1 | 実装は既存のプロジェクトスタイル（TypeScript, Next.js App Router, zod, Prisma, `@umami/react-zen`）に準拠する。 |
| NFR-2 | メモフィールドの追加によって既存のAPIレスポンス構造・既存クライアントの動作に破壊的変更を生じさせない（後方互換性を維持する）。 |
| NFR-3 | メモの保存・取得は既存のウェブサイト更新・取得のパフォーマンス特性を大きく劣化させない（追加フィールド1つ程度の想定）。 |
| NFR-4 | メモの文字数上限（500文字）はサーバー・クライアントで一貫した値とし、将来変更する場合も1箇所の定数変更で追従できることが望ましい。 |
| NFR-5 | 一覧画面での省略表示は、他のテーブル列のレイアウト・可読性を損なわないこと。 |

## 5. ユーザーストーリー

**US-201: サイト運用者として、登録している各ウェブサイトにメモを書き残しておきたい。**
ウェブサイトが増えても、名前とドメインだけでは判別できない「本番/検証用」「依頼者」等の情報をメモとして残し、後から一覧・詳細で確認できるようにするため。

## 6. 受け入れ条件（Acceptance Criteria）

### AC-1: メモの入力・保存（設定詳細画面）
- Settings → Websites → 対象ウェブサイトの編集画面に、メモを入力する欄が表示される。
- メモを入力して保存すると、成功メッセージが表示され、値が保存される。

### AC-2: メモの永続化
- メモを保存後、画面をリロードしても、編集画面に入力したメモがそのまま表示される。

### AC-3: 一覧画面での表示（メモあり）
- メモが設定されているウェブサイトは、一覧画面にそのメモの内容（またはその省略表示）が表示される。

### AC-4: 一覧画面での表示（メモなし）
- メモが未設定（null/空）のウェブサイトは、一覧画面にメモに関する表示が一切出ない。

### AC-5: 文字数上限
- メモに500文字を超える文字列を入力して保存しようとすると、保存が拒否され、エラーが表示される（画面上・API上どちらでも上限超過を検知できる）。
- 500文字以内のメモは正常に保存できる。

### AC-6: 既存ウェブサイトの後方互換性
- メモが設定されていない既存のウェブサイトについて、詳細画面の表示・編集、一覧画面の表示、他の設定項目（名前・ドメイン等）の更新がエラーなく従来通り行える。

### AC-7: 権限制御
- ウェブサイトの更新権限を持たないユーザーがメモの更新を試みた場合（APIへの直接リクエストを含む）、更新は拒否される（unauthorizedエラー等）。
- 更新権限を持つユーザーは、メモの更新に成功する。

## 7. 疑問点・確認事項（Open Questions）

以下は要望文からは一意に確定できないため、実装時に既存実装スタイルに合わせて判断するか、別途確認が必要な事項。

1. **一覧画面での省略表示の具体的な文字数・方式**: 「長い場合は省略表示でよい」とのみ指定されており、何文字で省略するか、ツールチップ等で全文表示するかは未確定。既存の他カラムの省略表示パターンがあればそれに合わせる想定。
2. **文字数上限の厳密な値**: 「500文字程度」と幅を持った表現のため、厳密に500文字固定か、多少の前後は許容されるかは要確認。本書では500文字を上限として扱う。
3. **共有リンク（Share）経由でメモを閲覧可能とするか**: 要望文に明記がないため、通常の閲覧権限を持つユーザーと同様に表示するか、共有ビューでは非表示にするかは未確定。
4. **管理者（Admin）用ウェブサイト一覧・詳細画面（`admin/websites`）にもメモ表示・編集を含めるか**: 要望は「Settings → Websites」のみを明示しており、管理者専用画面への適用要否は未確定。
