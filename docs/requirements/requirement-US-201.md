# 要件定義書 US-201: ウェブサイトへのメモ（notes）追加

## 1. 背景・目的

### 課題
サイト運用者は umami に複数のウェブサイトを登録して運用しているが、サイト数が増えると
「どれが本番でどれが検証用か」「誰の依頼で作成したサイトか」といった付帯情報を
サイト名・ドメインだけから判別できなくなっている。

### 目的
ウェブサイトに自由記述の「メモ（notes）」を持たせ、運用者が用途・依頼元などの
補足情報を記録・参照できるようにする。

### 対象ユーザー
- サイト運用者（umami にウェブサイトを登録・管理する権限を持つユーザー）

### 成功指標
- ウェブサイト設定画面でメモを入力・編集・保存でき、再読み込み後も内容が保持される。
- ウェブサイト一覧でメモの有無・概要が視認でき、どのサイトが何のためのものか判別しやすくなる。

## 2. スコープ

### 対象（Must / Should）
- ウェブサイト設定の編集画面（Settings → Websites → 対象サイトの編集画面）にメモ入力欄を追加する。
- メモの新規入力・編集・保存機能（永続化）。
- ウェブサイト一覧画面でのメモの表示（長文は省略表示、未入力時は非表示）。
- メモの文字数上限（500文字程度）のバリデーション。上限超過時は保存不可。
- 既存ウェブサイト（メモ未設定＝null/空）に対する後方互換性（エラーなく従来通り動作）。
- ウェブサイト更新権限を持たないユーザーによるメモ書き換えの防止（権限制御）。

### 対象外（Won't）
- メモの変更履歴・バージョン管理。
- メモへのリッチテキスト・添付ファイル対応（プレーンテキストのみ）。
- メモを用いた検索・フィルタリング機能。
- メモの多言語対応・翻訳機能。
- メモに対する通知・アラート機能。
- API 経由の外部連携（webhook 等）でのメモ公開。

## 3. 用語定義

| 用語 | 定義 |
|---|---|
| メモ（notes） | ウェブサイトに紐づく自由記述のテキスト情報。運用者向けの補足メモ。 |
| ウェブサイト設定編集画面 | Settings → Websites → 対象サイトをクリックした際に表示される編集フォーム。 |
| ウェブサイト一覧 | Settings → Websites で表示される、登録済みウェブサイトの一覧画面。 |
| 更新権限 | 対象ウェブサイトを編集（update）できる権限。既存の権限モデルに準拠。 |

## 4. 機能要件（ユーザーストーリー・受け入れ条件）

### US-201-1: メモの入力・編集
**ユーザーストーリー**
サイト運用者として、ウェブサイト設定の編集画面でメモを入力・編集したい。
なぜなら、そのサイトの用途や依頼元などの補足情報を残しておきたいから。

**受け入れ条件**
- Given ウェブサイト設定編集画面を開いている
  When メモ欄に任意のテキスト（500文字以内）を入力し保存する
  Then メモが保存され、成功のフィードバック（トースト等、既存の保存成功時の挙動に準拠）が表示される。
- Given メモが既に設定されているウェブサイトの編集画面を開いている
  When 画面を表示する
  Then メモ欄に既存の内容が表示される。
- Given メモを編集した
  When 保存する
  Then 変更後の内容で上書き保存される。
- Given メモ欄を空にして保存する
  When 保存操作を行う
  Then メモは空（未入力）として保存され、エラーにならない。

### US-201-2: メモの永続化
**ユーザーストーリー**
サイト運用者として、保存したメモが画面を再読み込みしても消えないようにしたい。
なぜなら、都度入力し直す手間を避けたいから。

**受け入れ条件**
- Given メモを保存した
  When ブラウザをリロードする、または再度編集画面を開く
  Then 保存したメモの内容がそのまま表示される。
- Given メモを保存した
  When 別セッション・別ブラウザから同じウェブサイトの編集画面を開く
  Then 同じメモ内容が表示される（サーバー側に永続化されている）。

### US-201-3: ウェブサイト一覧でのメモ表示
**ユーザーストーリー**
サイト運用者として、ウェブサイト一覧を見ただけでどのサイトにどんなメモが付いているか把握したい。
なぜなら、一覧から本番/検証用などをすぐ判別したいから。

**受け入れ条件**
- Given メモが設定されているウェブサイトが一覧に含まれる
  When 一覧画面を表示する
  Then そのサイトの行にメモの内容（または省略表示）が確認できる。
- Given メモが未入力（null/空文字）のウェブサイトが一覧に含まれる
  When 一覧画面を表示する
  Then そのサイトの行にはメモに関する表示が何も出ない（プレースホルダーやラベルも含め非表示）。
- Given メモが長文（表示領域を超える長さ）である
  When 一覧画面を表示する
  Then メモは省略表示（例: 末尾を省略記号で切り詰め）される。

### US-201-4: メモの文字数上限
**ユーザーストーリー**
サイト運用者として、メモが際限なく長くならないようにしてほしい。
なぜなら、UI の表示崩れやデータの肥大化を防ぎたいから。

**受け入れ条件**
- Given メモ欄に500文字以内のテキストを入力する
  When 保存する
  Then 保存に成功する。
- Given メモ欄に500文字を超えるテキストを入力する
  When 保存を試みる
  Then 保存は拒否され、エラーメッセージが表示される（クライアント側・サーバー側の両方でバリデーション）。

### US-201-5: 既存ウェブサイトとの後方互換性
**ユーザーストーリー**
サイト運用者として、メモ機能追加後も既存のウェブサイト（メモ未設定）が問題なく動作してほしい。
なぜなら、既存運用に影響を与えたくないから。

**受け入れ条件**
- Given メモ機能導入前から存在する既存ウェブサイト（メモ列が null）
  When 一覧・編集画面・API を利用する
  Then エラーが発生せず、これまでどおり表示・編集・保存ができる。
- Given メモ機能導入前の既存ウェブサイトを開く
  When 編集画面を表示する
  Then メモ欄は空欄として表示される。

### US-201-6: 権限制御
**ユーザーストーリー**
サイト運用者として、ウェブサイトの更新権限を持たないユーザーにメモを書き換えられたくない。
なぜなら、意図しない情報改ざんを防ぎたいから。

**受け入れ条件**
- Given 対象ウェブサイトの更新権限を持たないユーザーでログインしている
  When メモを含む更新リクエストを送信する（画面操作・API直接呼び出しいずれも）
  Then 更新は拒否され、権限エラー（既存の更新API権限チェックと同様のレスポンス）が返る。
- Given 対象ウェブサイトの更新権限を持たないユーザーでログインしている
  When 編集画面を開く（閲覧権限がある場合）
  Then メモは閲覧できるが、編集・保存操作はできない（保存ボタンの無効化またはサーバー側での拒否）。
- Given 対象ウェブサイトの更新権限を持つユーザーでログインしている
  When メモを更新する
  Then 既存の更新権限ロジックに従い、更新が成功する。

## 5. 非機能要件

| 分類 | 要件 | 優先度 |
|---|---|---|
| データ整合性 | メモは既存の Website モデルに対する後方互換なスキーマ変更（追加カラムは nullable）とする。 | Must |
| セキュリティ・権限 | メモの更新は既存のウェブサイト更新権限チェック（authorization）の対象に含める。閲覧は既存の閲覧権限に準拠。 | Must |
| バリデーション | 文字数上限（500文字）はクライアント（フォーム入力）・サーバー（API/スキーマ）の両方で検証する（zod 等既存のバリデーション基盤を利用）。 | Must |
| 一貫性・実装スタイル | 既存実装のスタイル（TypeScript, Next.js App Router, zod, Prisma, `@umami/react-zen`）に準拠する。 | Must |
| 可用性 | メモ機能追加によって既存のウェブサイト一覧・編集・保存フローの可用性・パフォーマンスを損なわないこと（追加カラム1つ程度で大きな性能影響は想定しない）。 | Should |
| 国際化 | メモの入力・表示自体は特定言語に限定しないが、UI ラベル文言は既存の多言語対応（i18n）の仕組みに則って追加する。 | Should |
| 監査性 | メモの変更履歴は本スコープでは扱わない（対象外に明記済み）。 | Won't（対象外） |

## 6. MoSCoW 優先度まとめ

| 要件 | 優先度 |
|---|---|
| メモの入力・編集・保存（編集画面） | Must |
| メモの永続化 | Must |
| 文字数上限バリデーション（500文字、クライアント/サーバー両方） | Must |
| 既存ウェブサイトとの後方互換性 | Must |
| 更新権限のないユーザーへの書き換え防止 | Must |
| ウェブサイト一覧でのメモ表示（省略表示、未入力時非表示） | Should |
| UI 文言の i18n 対応 | Should |
| メモの変更履歴管理 | Won't |
| メモを使った検索・フィルタ | Won't |
| リッチテキスト・添付ファイル対応 | Won't |

## 7. 未決事項・前提・オープンクエスチョン

1. **文字数上限の厳密な値**: brief.md では「500文字程度」とあり、厳密に500か、それより多少前後してよいかは明記されていない。
   → **前提**: 本要件では上限を **500文字（全角・半角問わず文字数でカウント）** とし、500文字ちょうどは許可、501文字以上を拒否とする。
2. **一覧画面での省略表示の具体的な文字数・行数**: brief.md に具体的な文字数指定なし。
   → **前提**: 具体的な文字数・行数は固定値として定義せず、frontend-engineer がUI実装時に調整できる裁量事項とする（例: 1行・50〜100文字程度で末尾を省略記号にする等はあくまで一案）。要件としては「長い場合は省略表示」という定性的な条件のみを定義し、詳細な表示仕様はUI実装フェーズで決定・調整する。
3. **メモのフィールド名・DB上のカラム名**: brief.md により実装スタイルに合わせるとされているため、本書では論理名「notes」として扱い、物理名（DBカラム名・API フィールド名）の具体は設計フェーズ（backend-architect）に委ねる。
4. **権限チェックの粒度**: 「ウェブサイトを更新する権限がないユーザー」が具体的にどのロール（Viewer相当等）を指すかは、既存の権限モデル（Team/Website の role）に準拠する前提とし、本書では新たな権限区分は設けない。
5. **メモの入力可能文字種**: 絵文字・改行・特殊文字の扱いについて brief.md に明記なし。
   → **前提**: プレーンテキストとして自由入力を許可し、特別な文字種制限は設けない（実装スタイルに合わせて既存の自由記述フィールドと同様の扱いとする）。

以上、疑問点は前提を置いた上で要件を確定した。実装・設計判断が必要な項目（DBカラム名、UIの詳細な省略表示仕様等）は次工程（backend-architect / frontend-engineer）へ引き継ぐ。
