## 1. 背景・目的

### 1.1 背景（なぜ必要か）
サイト運用者は umami に複数のウェブサイトを登録して運用している。ウェブサイトの数が増えると、**名前とドメインだけでは各サイトの用途や文脈が判別できなくなる**。具体的には次のような情報がどこにも残せない。

- どれが本番環境で、どれが検証用か
- 誰の依頼で作成したサイトか
- その他、運用上の覚え書き

### 1.2 目的
登録済みの各ウェブサイトに **自由記述のメモ（notes）** を持たせ、運用者が用途・経緯・担当などの文脈情報を書き残し、あとから一覧・詳細で確認できるようにする。

### 1.3 対象ユーザー / ステークホルダー
- **主対象**: サイト運用者（対象ウェブサイトの更新権限を持つユーザー）。メモの入力・編集・閲覧を行う。
- **副対象**: 更新権限を持たない閲覧ユーザー。メモの閲覧は可能だが編集はできない（詳細は非機能・権限要件を参照。※オープンクエスチョン Q3）。

### 1.4 成功指標（どうなれば成功か）
- ウェブサイト編集画面でメモを入力・保存でき、再読み込み後も保持されている。
- ウェブサイト一覧でメモの有無・内容（要約）が判別できる。
- 既存のメモ未設定サイトが、これまでどおりエラーなく動作する。
- 更新権限のないユーザーがメモを改変できない。

---

## 2. スコープ

### 2.1 対象（やること）
1. ウェブサイトエンティティに自由記述メモ（notes）を格納するフィールドを追加する。
2. ウェブサイト設定の詳細（Settings → Websites → 対象サイトの編集画面）でメモを入力・編集・保存できる。
3. 保存したメモを永続化し、画面再読み込み後も保持する。
4. ウェブサイト一覧でメモの内容を確認できるようにする（長い場合は省略表示。未入力サイトには何も表示しない）。
5. メモの文字数上限（500文字程度）を設け、超過時は保存させずエラーを返す。
6. 既存のメモ未設定ウェブサイトの後方互換を保つ。
7. 更新権限に基づくメモ編集の認可を行う。

### 2.2 対象外（やらないこと / Won't）
- メモの履歴管理・版管理・変更ログ。
- メモに対する全文検索・フィルタ・並べ替え機能。
- リッチテキスト、Markdown レンダリング、添付ファイル、メンション等の高度な編集機能。
- 複数メモ（1サイトに対しメモは単一フィールド）。
- メモに対する通知・共有・公開（共有ページへの露出）。
- メモの多言語化（メモ本文そのものの翻訳）。

## 3. 機能要件（ユーザーストーリー & 受け入れ条件）

優先度は MoSCoW で表記。Must = MVP。

### US-201-1: メモの入力・保存（Must）
**サイト運用者として**、ウェブサイト設定の詳細画面でメモを入力・保存したい。**なぜなら**、そのサイトの用途や経緯を書き残しておきたいから。

受け入れ条件（Given/When/Then）:
- **AC-1.1**: Given 更新権限のあるユーザーが対象サイトの編集画面を開いている、When メモ入力欄に文字列を入力して保存する、Then メモが保存され、保存成功のフィードバック（トースト等）が表示される。
- **AC-1.2**: Given メモを保存した、When 画面を再読み込みする、Then 入力したメモが編集画面に表示される（永続化されている）。
- **AC-1.3**: Given 既存メモがある、When 内容を書き換えて保存する、Then 新しい内容で上書き保存される。
- **AC-1.4**: Given メモ入力欄を空にして保存する、When 保存する、Then メモは「未設定（空）」として保存され、エラーにならない。

### US-201-2: 文字数上限のバリデーション（Must）
**サイト運用者として**、メモが長くなりすぎないよう上限を設けてほしい。**なぜなら**、メモが肥大化するのを防ぎたいから。

受け入れ条件:
- **AC-2.1**: Given メモが上限（500文字）以内、When 保存する、Then 正常に保存される。
- **AC-2.2**: Given メモが上限（500文字）を超える、When 保存しようとする、Then 保存は行われず、バリデーションエラーが返る（サーバ側で 400 相当のエラー、クライアント側でもエラー表示）。
- **AC-2.3**: 上限判定は **文字数 = 500** を境界とする（500文字は許可、501文字は不許可）。※境界値は brief の「500文字程度」に基づく既定値。変更可能性は Q1 参照。

### US-201-3: 一覧でのメモ表示（Must）
**サイト運用者として**、ウェブサイト一覧でどのサイトにどんなメモが付いているか把握したい。**なぜなら**、名前とドメインだけでは用途が判別できないから。

受け入れ条件:
- **AC-3.1**: Given メモが設定されたサイト、When ウェブサイト一覧を表示する、Then そのサイトのメモ（要約/省略表示）が確認できる。
- **AC-3.2**: Given メモが長い、When 一覧に表示する、Then 省略表示（truncate 等）され、レイアウトが崩れない。
- **AC-3.3**: Given メモが未入力のサイト、When 一覧を表示する、Then そのサイトにはメモ表示が一切出ない（空欄・プレースホルダも含めて出さない）。

### US-201-4: 権限による編集制御（Must）
**運用管理者として**、更新権限のないユーザーがメモを改変できないようにしたい。**なぜなら**、運用情報の不正な書き換えを防ぎたいから。

受け入れ条件:
- **AC-4.1**: Given 対象サイトの更新権限がないユーザー、When メモ更新を要求する（API直叩き含む）、Then 更新は拒否され、認可エラー（401/403 相当）が返る。
- **AC-4.2**: Given 更新権限のないユーザー、When 既存の権限制御（サイト名・ドメイン更新と同じ経路）でメモ更新を試みる、Then メモ更新はサイト更新権限（既存 `canUpdateWebsite` 相当）と同一のルールで制御される。
- **AC-4.3**: メモ閲覧の可否は、サイト閲覧権限（既存 `canViewSharedWebsite` 相当）に準拠する。※共有ページでの露出可否は Q2 参照。

### US-201-5: 後方互換（Must）
**既存ユーザーとして**、既にあるサイト（メモ未設定）がこれまでどおり動いてほしい。

受け入れ条件:
- **AC-5.1**: Given メモ未設定の既存サイト、When 編集画面・一覧・詳細を表示する、Then エラーが発生せず従来どおり表示される。
- **AC-5.2**: Given 既存サイトのメモがデータ上未設定（null/空）、When name/domain 等の既存項目のみ更新する、Then メモは未設定のまま保持され、既存更新は成功する。
- **AC-5.3**: メモフィールドは任意（nullable / optional）であり、未設定を許容する。

## 4. 非機能要件

| 分類 | 要件 |
| --- | --- |
| パフォーマンス | メモ追加による一覧・詳細のレスポンス劣化がないこと。一覧は既存クエリに追加取得する程度で、N+1 を発生させない。 |
| データ整合性 | メモは対象ウェブサイトに1対1で紐づく。ウェブサイト削除時はメモも一緒に扱われる（別テーブルにしない前提では自動）。 |
| セキュリティ | 更新は既存の認可（`canUpdateWebsite`）に準拠。入力はサーバ側 zod でバリデーション（クライアント検証だけに依存しない）。XSS 防止のため表示時は既存の React エスケープに委ねる（生 HTML 挿入をしない）。 |
| バリデーション | 文字数上限（500）はサーバ側 zod スキーマで担保。クライアント側でも同等のガイドを表示するのが望ましい（Should）。 |
| 互換性 | 既存 API の後方互換を維持。メモは追加の optional フィールドとし、未指定時は既存挙動を変えない。 |
| 実装スタイル | 既存実装様式に準拠すること: TypeScript / Next.js App Router / zod / Prisma / `@umami/react-zen`。フィールド名・UI 文言・配置は既存の命名（例: `name`, `domain`）に馴染む形（例: `notes`）とする。 |
| 国際化 | UI ラベル・メッセージは既存の i18n（`useMessages` / `labels` / `messages`）の仕組みに沿って追加する。 |
| 運用/マイグレーション | Prisma スキーマ変更に伴う DB マイグレーションを用意。既存データに対しては nullable 追加のため後方互換で適用可能。 |

## 5. 実装上の位置づけ（既存コードとの対応 / 参考情報）

> 設計・実装は行わないが、要件を検証可能にするため既存の該当箇所を参照情報として示す。

- データモデル: `prisma/schema.prisma` の `model Website`（`name`, `domain` 等と並ぶ optional フィールドとして `notes` を追加する想定）。
- 更新 API: `src/app/api/websites/[websiteId]/route.ts` の `POST`（zod schema に `notes` を追加、`canUpdateWebsite` で認可済み）。
- 更新クエリ: `src/queries/prisma/website.ts` の `updateWebsite`。
- 編集フォーム: `src/app/(main)/websites/[websiteId]/settings/WebsiteEditForm.tsx`（`name`/`domain` と同様に `notes` 入力欄を追加）。
- 一覧: `src/app/(main)/settings/websites/WebsitesSettingsPage.tsx`（メモの省略表示を追加）。

## 6. 用語定義

| 用語 | 定義 |
| --- | --- |
| メモ / notes | ウェブサイトに紐づく自由記述のテキスト。用途・経緯・担当などの覚え書き。 |
| 省略表示 | 長いメモを一覧で切り詰めて表示すること（truncate、末尾に「…」等）。 |
| 更新権限 | 対象ウェブサイトを更新できる権限（既存の `canUpdateWebsite` に準拠）。 |

## 7. 前提・オープンクエスチョン（未決事項）

| ID | 種別 | 内容 | 暫定方針 |
| --- | --- | --- | --- |
| Q1 | 上限値 | 「500文字程度」の厳密な上限。文字数カウント方法（コードポイント/書記素/サロゲート）も未定。 | 既定値 **500文字**（`z.string().max(500)` 相当、JS `length` 準拠）で実装し、必要なら調整。 |
| Q2 | 露出範囲 | メモを共有ページ（公開ページ）にも表示するか。 | **表示しない**（対象外）。運用者向け内部情報とみなす。 |
| Q3 | 閲覧権限 | 更新権限のない閲覧ユーザーにメモを見せてよいか。 | サイト閲覧権限があれば閲覧可（`canViewSharedWebsite` 準拠）。要ステークホルダー確認。 |
| Q4 | 表示箇所 | 「ウェブサイト一覧」は Settings→Websites 一覧を指すのか、他のダッシュボード一覧も含むのか。 | Settings→Websites 一覧を対象と解釈。他一覧への展開は Should/対象外。 |
| Q5 | 空白の扱い | 前後空白のトリム有無、空白のみの入力を「未設定」とみなすか。 | 前後トリムし、トリム後空なら「未設定（空）」として扱う想定。 |
| Q6 | 改行 | 複数行メモ（改行）を許可するか、一覧でどう省略するか。 | 複数行入力可（textarea 想定）。一覧では1行に省略表示。 |

## 8. 優先度サマリ（MoSCoW / MVP）

- **Must（MVP）**: US-201-1（入力・保存）、US-201-2（上限バリデーション）、US-201-3（一覧表示）、US-201-4（権限制御）、US-201-5（後方互換）。
- **Should**: クライアント側の文字数カウンタ・残文字数表示、複数行対応の一覧省略の最適化。
- **Could**: 一覧でのメモ列の表示/非表示トグル。
- **Won't（今回対象外）**: メモ履歴、検索/フィルタ、リッチテキスト、共有ページ露出、複数メモ。
