# 要件定義書: US-201 ウェブサイトへのメモ（notes）機能

- ストーリーID: US-201
- 対象プロダクト: umami
- 作成者: requirements-analyst
- ステータス: ドラフト（要件定義フェーズ）

---

## 1. 背景・目的

### 1.1 解決したい課題
サイト運用者は umami に多数のウェブサイトを登録して運用している。ウェブサイトが増えると、
一覧に表示される「名前」と「ドメイン」だけでは、以下が判別しにくくなる。

- どれが本番環境で、どれが検証（ステージング）用か
- 誰の依頼で作ったサイトか、どんな経緯・用途か

その結果、サイトの取り違え・確認コスト増・運用ミスのリスクが生じる。

### 1.2 目的（提供価値）
登録済みの各ウェブサイトに自由記述の **メモ（notes）** を残せるようにし、
運用上の補足情報（本番/検証の区別、依頼元、用途など）をサイトに紐づけて管理できるようにする。
これにより、名前とドメイン以外の文脈情報を素早く把握でき、取り違えや確認コストを減らす。

### 1.3 成功指標（どうなれば成功か）
- ウェブサイト設定画面でメモを入力・保存でき、再読み込み後も保持されている。
- ウェブサイト一覧で、メモの有無・内容の概要を確認できる。
- 既存サイト（メモ未設定）が従来どおり動作し、機能追加による退行が発生しない。

---

## 2. ステークホルダー / 対象ユーザー

| 区分 | 説明 | メモに対する関心 |
| --- | --- | --- |
| サイト運用者（主対象） | ウェブサイトを登録・設定・分析する利用者 | メモの閲覧・入力・編集・保存 |
| 更新権限を持たないユーザー | 対象ウェブサイトの閲覧はできるが更新権限を持たない利用者（共有先など） | メモの改変ができないこと（保護対象） |

---

## 3. 用語定義

- **メモ（notes）**: ウェブサイトに紐づく自由記述テキスト。運用上の補足情報を記録する。
- **ウェブサイト設定の詳細**: Settings → Websites → 対象サイトの編集画面（`WebsiteEditForm` を含む設定画面）。
- **省略表示**: 一覧などで長いテキストを途中で切り、全体を表示しないこと（例: 末尾を「…」で省略）。

---

## 4. スコープ

### 4.1 対象（やること）
- ウェブサイトに 1 件のメモ（自由記述テキスト）フィールドを追加する。
- ウェブサイト設定の詳細画面で、メモの表示・入力・編集・保存を行う。
- メモの永続化（再読み込み後も保持）。
- ウェブサイト一覧で、メモが設定されているサイトについてメモの内容（長い場合は省略表示）を確認できる。
- メモの文字数上限（約 500 文字）を設け、超過時は保存させない（バリデーション）。
- 既存ウェブサイト（メモ未設定）との後方互換の担保。
- 更新権限を持たないユーザーによるメモ改変の防止（サーバー側での権限チェック）。

### 4.2 対象外（やらないこと）
- 複数メモ・メモ履歴・バージョン管理・変更履歴の保持。
- リッチテキスト、Markdown レンダリング、添付ファイル、画像埋め込み。
- メモに対する検索・フィルタ・並び替え・タグ付け。
- メモの共有ページ（公開ページ）への表示。
- メモ単体の専用 API エンドポイントの新設（既存のウェブサイト更新の枠組みに載せる想定。詳細は設計フェーズ）。
- メモに関する通知・監査ログ・多言語での本文自動翻訳。

## 5. 機能要件

各要件に MoSCoW 優先度を付す（Must / Should / Could / Won't）。

### FR-1【Must】メモの入力・編集
ウェブサイト設定の詳細画面に、メモ入力用の複数行テキスト入力欄を設ける。
既存のフォームスタイル（`@umami/react-zen` の `Form`/`FormField` 等）になじむ形とする。

- なぜ: 運用者が補足情報を記録できることが本機能の中核価値であるため。

### FR-2【Must】メモの保存・永続化
入力したメモを保存でき、保存後に画面を再読み込みしてもメモが保持されている。

- なぜ: 一時的な表示では運用の補助にならず、永続化が価値の前提となるため。

### FR-3【Must】メモの文字数上限バリデーション
メモは約 500 文字を上限とし、上限を超える場合は保存を許可せず、ユーザーに分かる形でエラーを示す。
上限以内（境界の 500 文字を含む）は保存できる。

- なぜ: 過度に長いメモによる UI 崩れ・データ肥大を防ぎ、要望どおり簡潔な補足に留めるため。
- 補足: 500 文字は「程度」の要望。厳密値は仮決めとし、未決事項 OQ-1 で確認する。

### FR-4【Must】一覧でのメモ表示
ウェブサイト一覧で、メモが設定されているサイトについてメモ内容を確認できる。
長い場合は省略表示でよい。**メモが未入力のサイトには何も表示しない**（空欄や余計なラベルを出さない）。

- なぜ: 一覧の段階で本番/検証や依頼元などの文脈を素早く把握できるようにするため。

### FR-5【Must】権限による改変防止
対象ウェブサイトを更新する権限がないユーザーは、メモを書き換えられない。
権限チェックはサーバー側で行い、クライアント表示だけの制御に依存しない。

- なぜ: 権限のないユーザーによるデータ改変はセキュリティ・運用統制上許容できないため。
- 補足: 既存のウェブサイト更新権限（`canUpdateWebsite` 相当）に準拠する。

### FR-6【Must】後方互換（既存サイト）
メモが未設定の既存ウェブサイトでも、一覧・設定画面・更新処理がエラーにならず従来どおり動作する。
メモ未設定は「空」または「未設定」として扱い、必須項目にはしない（メモは任意入力）。

- なぜ: 既存データを壊さず段階的に導入するため。

### FR-7【Should】メモのクリア（空にする）
一度保存したメモを空文字にして保存でき、その結果メモ未設定と同等（一覧に何も出ない）状態に戻せる。

- なぜ: 誤登録・不要になった情報を消せることは編集機能として自然な要求であるため。

## 6. 非機能要件

### NFR-1【Must】既存実装スタイルとの整合
保存先・フィールド名・UI 文言/配置は既存実装スタイル（TypeScript / Next.js App Router / zod /
Prisma / `@umami/react-zen`）になじむ形にする。バリデーションはクライアント/サーバー双方で
既存パターン（zod スキーマ等）に沿って行う。

### NFR-2【Must】セキュリティ
- サーバー側で更新権限を検証してからメモ更新を反映する（FR-5）。
- メモは自由記述テキストのため、表示時に XSS 等が起きないよう既存のエスケープ/描画方針に従う。
- 文字数上限をサーバー側でも検証し、クライアント検証のバイパスを防ぐ。

### NFR-3【Should】データ整合・移行
既存の `Website` にメモ用フィールドを追加する場合、NULL 許容（任意）とし、既存レコードへの
マイグレーションが安全（デフォルト空/NULL）で、ダウンタイムや既存データ破壊を伴わないこと。

### NFR-4【Should】パフォーマンス
一覧表示でのメモ取得・省略表示が、既存の一覧表示パフォーマンスを著しく劣化させないこと。

### NFR-5【Could】アクセシビリティ／UX
メモ入力欄にラベルを付与し、上限超過時のエラーメッセージが明確であること。省略表示された
メモの全文確認手段（例: 詳細画面での参照）が存在すること。

## 7. ユーザーストーリーと受け入れ条件（Given/When/Then）

> 受け入れ条件は test-engineer がそのままテストに落とせる粒度で記述する。

### ストーリー US-201
> サイト運用者として、登録している各ウェブサイトに自由記述のメモを書き残しておきたい。
> なぜなら、名前とドメインだけでは本番/検証の区別や依頼元が分からなくなるから。

#### AC-1: 設定画面でメモを入力・保存できる（FR-1, FR-2）
- Given: 更新権限を持つユーザーが対象ウェブサイトの設定詳細画面を開いている
- When: メモ欄に任意のテキストを入力して保存する
- Then: 保存が成功し、保存完了が通知される

#### AC-2: 保存したメモが永続化される（FR-2）
- Given: メモを入力して保存済みである
- When: 同じ設定詳細画面を再読み込みする
- Then: 保存したメモが入力欄に表示される

#### AC-3: 一覧でメモが確認できる（FR-4）
- Given: あるウェブサイトにメモが設定されている
- When: ウェブサイト一覧を表示する
- Then: そのサイトの行でメモ内容が確認でき、長い場合は省略表示される

#### AC-4: メモ未設定サイトは一覧に何も出ない（FR-4, FR-6）
- Given: メモが未設定（空）のウェブサイトが存在する
- When: ウェブサイト一覧を表示する
- Then: そのサイトの行にはメモに関する表示（空欄ラベル等）が出ず、従来どおりの表示となる

#### AC-5: 上限以内のメモは保存できる（FR-3）
- Given: 更新権限を持つユーザーが設定詳細画面を開いている
- When: 上限文字数ちょうど（例: 500 文字）のメモを入力して保存する
- Then: 保存が成功する

#### AC-6: 上限超過のメモは保存できない（FR-3, NFR-2）
- Given: 更新権限を持つユーザーが設定詳細画面を開いている
- When: 上限を超える文字数（例: 501 文字）のメモを入力して保存しようとする
- Then: 保存は行われず、上限超過が分かるエラーが表示される（サーバー経由でも拒否される）

#### AC-7: 更新権限のないユーザーはメモを改変できない（FR-5, NFR-2）
- Given: 対象ウェブサイトの更新権限を持たないユーザーである
- When: メモの更新（保存）を試みる
- Then: 更新は拒否され（サーバー側で権限エラー）、メモは変更されない

#### AC-8: 既存サイト（メモ未設定）が従来どおり動作する（FR-6）
- Given: メモ機能追加前から存在する、メモ未設定のウェブサイトがある
- When: 一覧表示・設定詳細画面表示・ウェブサイト更新（名前/ドメイン等）を行う
- Then: いずれもエラーにならず、従来どおり動作する

#### AC-9: メモをクリアして未設定状態に戻せる（FR-7）
- Given: メモが保存済みのウェブサイトがある
- When: メモ欄を空にして保存する
- Then: 保存が成功し、一覧でメモ表示が出ない（未設定と同等の）状態になる

---

## 8. 前提・制約

- 保存先/フィールド名/UI 文言・配置は既存スタイル（TS / Next.js App Router / zod / Prisma /
  `@umami/react-zen`）に合わせる（NFR-1）。
- メモは 1 ウェブサイトにつき 1 件、任意入力、プレーンテキスト。
- 権限は既存のウェブサイト更新権限に準拠する（新規の権限体系は作らない）。
- 本ドキュメントは要件定義のみを扱い、実装・設計・テストコードは含まない。

---

## 9. エッジケース・異常系チェック

- 空文字保存: 未設定と同等に扱う（FR-7, AC-9）。
- 上限境界: 上限ちょうどは可、上限+1 は不可（AC-5, AC-6）。
- 前後の空白のみ / 改行のみのメモ: 文字数カウント・保存可否の扱いを設計時に明確化（OQ-2）。
- マルチバイト（日本語等）・絵文字: 文字数カウント基準（コードポイント/文字数）を統一する（OQ-1）。
- 権限バイパス: クライアント検証を無視した直接リクエストでもサーバー側で拒否（AC-6, AC-7）。
- 同時編集: 別ユーザー/別タブでの同時更新時の上書き挙動は既存のウェブサイト更新と同一とする。
- 未設定既存レコード: NULL/空をエラーなく扱う（AC-8）。

---

## 10. 未決事項（オープンクエスチョン）

- OQ-1: 上限「500文字程度」の厳密値と数え方（コードポイント数か、UTF-16 長か、書記素か）。
  仮決め: 上限 500、コードポイント数で数える。要確認。
- OQ-2: 前後空白・改行のみの入力を「空（未設定）」とみなすか（トリム有無）。
  仮決め: 表示上は空とみなすが、保存値のトリム有無は設計で決定。
- OQ-3: 一覧での省略表示の具体的な文字数/幅、および全文の確認手段（ツールチップ or 詳細画面）。
- OQ-4: 権限のないユーザーに対して設定画面でメモ欄を「非表示」にするか「読み取り専用表示」にするか。
  （サーバー側拒否は必須。クライアント表示方針は UX として要確認。）
