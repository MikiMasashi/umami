# 要件定義書 US-201: ウェブサイトへのメモ（Notes）機能

## 1. 背景・目的

サイト運用者が umami に登録した各ウェブサイトに対して、自由記述の「メモ」を残せるようにする。
ウェブサイト数が増えると、名前とドメインだけでは「本番/検証用」「依頼元」などの識別が難しくなるため、
運用管理を補助する目的でメモ機能を追加する。

## 2. 対象範囲（スコープ）

### 2.1 対象（In Scope）

- ウェブサイト（`Website`）エンティティへの自由記述メモ（`notes`）の追加。
- ウェブサイト設定編集画面（Settings → Websites → 対象サイトの編集画面）でのメモの入力・編集・保存。
- メモの永続化（DB保存、画面再読み込み後も保持）。
- ウェブサイト一覧画面でのメモの表示（長い場合は省略表示、未入力時は非表示）。
- メモの文字数上限（500文字程度）のバリデーションと、超過時の保存拒否。
- 既存ウェブサイト（メモ未設定＝`null`）が後方互換的に動作すること。
- ウェブサイト更新権限（`canUpdateWebsite`）を持たないユーザーによるメモ書き換えの禁止。

### 2.2 対象外（Out of Scope）

- メモの検索・フィルタリング機能。
- メモの変更履歴・バージョン管理。
- メモに対するリッチテキスト／Markdown／添付ファイル等の高度な書式サポート。
- メモの共有リンク（Share機能）経由での閲覧者への公開可否の個別制御（既存の閲覧権限モデルに準拠する）。
- 複数言語対応の自動翻訳。
- 実装・設計・テストコードそのもの（本ドキュメントは要件定義のみ）。

## 3. 機能要件（Functional Requirements）

| ID | 要件 |
|----|------|
| FR-1 | ウェブサイト設定編集画面に、メモを入力するための自由記述テキスト入力欄（複数行）を追加する。 |
| FR-2 | ユーザーはメモを新規入力・編集・保存できる。保存後、画面を再読み込みしても入力内容が保持される（DBに永続化される）。 |
| FR-3 | メモは任意項目（必須ではない）とし、空欄でも保存できる。 |
| FR-4 | メモの最大文字数は500文字とし、超過した場合はクライアント側・サーバー側の両方でバリデーションエラーとし、保存を拒否する。 |
| FR-5 | ウェブサイト一覧画面に、各ウェブサイトのメモの内容（またはその一部）を表示する列・領域を追加する。 |
| FR-6 | ウェブサイト一覧でのメモ表示は、内容が長い場合は省略表示（例: 末尾を省略記号で切り詰め）とする。 |
| FR-7 | メモが未入力（空文字または未設定）のウェブサイトについては、一覧上に何も表示しない（空欄のままとし、代替テキスト等は表示しない）。 |
| FR-8 | 既存のウェブサイト（メモ未設定＝データベース上 `null` または未定義）は、エラーを起こさず従来どおり動作する（一覧表示・詳細表示・更新のいずれにおいても）。 |
| FR-9 | ウェブサイトを更新する権限（`canUpdateWebsite` に相当する既存の権限モデル）を持たないユーザーは、APIレベル・UIレベルの両方でメモの変更を行えない。 |
| FR-10 | メモの閲覧（一覧・詳細表示）は、既存のウェブサイト閲覧権限（`canViewWebsite`/`canViewSharedWebsite`）に準拠する。メモ専用の追加閲覧制限は設けない。 |

## 4. 非機能要件（Non-Functional Requirements）

| ID | 要件 |
|----|------|
| NFR-1 | 実装は既存の技術スタック（TypeScript, Next.js App Router, zod によるバリデーション, Prisma によるデータアクセス, `@umami/react-zen` によるUIコンポーネント）の実装スタイルに準拠すること。 |
| NFR-2 | 保存先（データベーススキーマ）のフィールド名、UIの文言・配置は、既存の命名規則・レイアウトパターンに倣うこと（例: `name`/`domain` と同様の扱い）。 |
| NFR-3 | メモの追加により、既存のウェブサイトAPI（取得・更新・一覧取得）のレスポンス互換性を大きく損なわないこと（既存フィールドを維持した上でのフィールド追加とする）。 |
| NFR-4 | 500文字程度の文字列を保持できるデータ型・カラムサイズとすること。 |
| NFR-5 | 既存のマイグレーション運用（Prismaマイグレーション）に沿った形でスキーマ変更を行うこと。 |

## 5. ユーザーストーリー

**US-201**
> サイト運用者として、登録している各ウェブサイトに「メモ」を書き残しておきたい。
> ウェブサイトが増えてくると、どれが本番でどれが検証用なのか、誰の依頼で作ったのかが
> 名前とドメインだけでは分からなくなるから。

### 関連する副次的ユーザーストーリー

- サイト運用者として、ウェブサイト一覧を見ただけで、各サイトの用途や依頼元がある程度分かるようにしたい。
- サイト運用者として、誤って長大なメモを保存して画面が崩れたり、DBを圧迫したりしないようにしてほしい。
- 権限を持たない閲覧専用ユーザーとして、他人が書いたメモを勝手に書き換えられないようにしてほしい（自分も書き換えられたくない）。

## 6. 受け入れ条件（Acceptance Criteria）

### AC-1: メモの入力・編集・保存（設定画面）
- **Given** ウェブサイト更新権限を持つユーザーが対象サイトの設定編集画面を開いている
- **When** メモ欄に任意の文字列（500文字以内）を入力して保存する
- **Then** 保存が成功し、成功メッセージ（既存の保存完了通知と同様の形式）が表示される

### AC-2: メモの永続化
- **Given** メモを保存済みのウェブサイトが存在する
- **When** 設定編集画面を再読み込みする、または再度開く
- **Then** 保存したメモの内容がそのまま表示される

### AC-3: メモの文字数上限超過
- **Given** ウェブサイト設定編集画面のメモ欄
- **When** 501文字以上のメモを入力して保存しようとする
- **Then** クライアント側でバリデーションエラーが表示され、保存が実行されない。仮にクライアント側の検証を回避してAPIに直接リクエストされた場合も、サーバー側で400系エラーが返され、保存されない

### AC-4: メモが空の場合の保存
- **Given** ウェブサイト設定編集画面のメモ欄が空欄
- **When** そのまま保存する
- **Then** エラーにならず保存が成功する（メモなしの状態として保存される）

### AC-5: ウェブサイト一覧でのメモ表示（入力あり）
- **Given** メモが設定されているウェブサイトが一覧に含まれる
- **When** ウェブサイト一覧画面を表示する
- **Then** そのウェブサイトの行にメモの内容（または省略表示）が表示される

### AC-6: ウェブサイト一覧での長いメモの省略表示
- **Given** 一覧の表示領域に収まらない長さのメモが設定されているウェブサイトがある
- **When** ウェブサイト一覧画面を表示する
- **Then** メモは省略表示され、UIのレイアウトが崩れない

### AC-7: ウェブサイト一覧でのメモ未入力時の表示
- **Given** メモが未設定（空欄）のウェブサイトが一覧に含まれる
- **When** ウェブサイト一覧画面を表示する
- **Then** そのウェブサイトの行にはメモに関する表示が何も出ない（プレースホルダーやダミーテキストも表示しない）

### AC-8: 既存ウェブサイト（メモ未設定）の後方互換動作
- **Given** メモ機能追加前から存在する、メモが `null`/未設定のウェブサイトデータ
- **When** 一覧表示、詳細表示、名前やドメインの更新（メモ以外の更新）を行う
- **Then** エラーが発生せず、従来どおりの動作をする

### AC-9: 権限のないユーザーによるメモ書き換えの禁止
- **Given** 対象ウェブサイトの更新権限を持たないユーザー（閲覧のみ可能なユーザー等）
- **When** メモを変更して保存しようとする（UI操作またはAPIへの直接リクエスト）
- **Then** UI上でメモの編集操作ができない、または保存APIが401/403相当のエラーを返し、メモは変更されない

### AC-10: 権限のあるユーザーによる閲覧
- **Given** 対象ウェブサイトの閲覧権限のみを持つユーザー（更新権限なし）
- **When** ウェブサイト一覧・詳細画面を表示する
- **Then** 既存の閲覧権限モデルに従い、メモの内容を閲覧できる（読み取り専用として表示される）

## 7. 疑問点・確認事項（Open Questions）

以下の点は本ブリーフのみからは一意に決定できないため、設計フェーズまでに確認・決定が必要な事項として記載する。

1. **文字数上限の厳密な値**: ブリーフでは「500文字程度」とされているが、正確に500文字を上限とするか、多少の幅（例: 500文字ちょうど、または512文字などDB都合の値）を持たせるかは未確定。本要件では暫定的に「500文字」を上限として記載した。
2. **一覧での省略表示の具体的な文字数・表示形式**: 「長い場合は省略表示でよい」とあるが、何文字で省略するか、ツールチップでの全文表示の要否などは未指定。
3. **メモの共有（Share）ビュー・公開ダッシュボードでの扱い**: メモを共有トークン経由の閲覧者（`shareToken` によるアクセス）にも見せてよいか、内部管理者専用情報として非表示にすべきかはブリーフに明記がない。本要件では「対象外」の運用ポリシーを設けず、既存の閲覧権限モデルに準拠する前提としたが、要確認。
4. **改行の扱い**: メモ入力欄が複数行（テキストエリア）を前提とするか、改行を含む入力を一覧表示でどう扱うか（改行を除去して1行表示するか等）は未指定。
5. **メモ変更の監査ログ要否**: 誰がいつメモを変更したかの記録が必要かはブリーフに記載がなく、対象外として扱ったが、運用上の要望があれば追加確認が必要。
