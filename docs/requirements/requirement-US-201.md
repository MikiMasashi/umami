# US-201 要件定義書（Website Notes）

## 1. 背景・目的
- **背景**: サイト数の増加により、サイト名とドメインだけでは用途（本番/検証）や依頼元などの運用文脈を判別しづらい。
- **目的**: Umami に登録済み Website ごとに運用メモを保持し、設定画面と一覧画面で参照できるようにして、運用判断ミスを減らす。
- **成功指標**:
  - Website 編集画面でメモを保存し、再読み込み後も内容が保持される。
  - Website 一覧でメモ有りサイトのみメモが視認できる（長文は省略表示）。
  - 権限のないユーザーはメモを更新できない。
  - 既存のメモ未設定サイトで回帰不具合が発生しない。

## 2. 対象ユーザー・ステークホルダー
- **主対象ユーザー**: サイト運用者（Website を管理・更新するユーザー）
- **ステークホルダー**: 分析基盤管理者、依頼元情報を運用管理するチーム

## 3. スコープ
### 3.1 対象（In Scope）
- Website に自由記述メモ（notes）を保持できること。
- Website 設定詳細画面でメモの入力・編集・保存ができること。
- Website 一覧画面でメモの表示ができること（長文省略表示）。
- メモ未入力時は一覧に表示しないこと。
- 文字数上限（500 文字）を超えるメモの保存を拒否すること。
- 権限チェックにより、Website 更新権限のないユーザーの書き換えを禁止すること。
- 既存 Website（notes 未設定）でも従来どおり動作すること。

### 3.2 対象外（Out of Scope）
- メモの履歴管理・監査ログ表示
- メモ内のリッチテキスト/Markdown 対応
- メモ検索・フィルタ機能
- 一覧での省略表示ルールを超える高度な表示制御（展開 UI、ツールチップ仕様追加など）

## 4. 機能要件
| ID | 要件 | 優先度 |
|---|---|---|
| FR-01 | Website は `notes` を 0..1 件保持できる。未設定（null/空）を許容する。 | Must |
| FR-02 | Website 設定詳細画面で `notes` の入力・編集・保存ができる。 | Must |
| FR-03 | 保存済み `notes` は永続化され、画面再読み込み後も同一内容を取得できる。 | Must |
| FR-04 | Website 一覧画面で `notes` がある Website のみメモを表示する。 | Must |
| FR-05 | 一覧表示は長文を省略表示する（全文をそのまま表示しない）。 | Should |
| FR-06 | `notes` が 500 文字を超える場合、保存を拒否し、利用者に入力超過を知らせる。 | Must |
| FR-07 | Website 更新権限のないユーザーは `notes` を更新できない。 | Must |
| FR-08 | 既存の `notes` 未設定 Website の閲覧・更新フローでエラーが発生しない。 | Must |

## 5. 非機能要件
| ID | 要件 | 優先度 |
|---|---|---|
| NFR-01 | 既存実装スタイル（TypeScript / Next.js App Router / zod / Prisma / `@umami/react-zen`）との整合を保つ。 | Must |
| NFR-02 | 入力バリデーションはサーバー側で強制され、クライアント側バリデーションと不整合を起こさない。 | Must |
| NFR-03 | 権限制御は既存 Website 更新権限制御と同等レベルで一貫性を保つ。 | Must |
| NFR-04 | `notes` 未設定データを含む既存データセットに対して後方互換性を保つ。 | Must |
| NFR-05 | 一覧で notes を追加表示しても、既存の実用操作に支障が出ない可読性を維持する。 | Should |

## 6. ユーザーストーリー
1. **運用者として**、Website の用途や背景情報をメモとして残したい。**なぜなら** サイト名とドメインだけでは運用判断に必要な文脈が不足するため。  
2. **運用者として**、Website 一覧で各サイトのメモ有無や内容要約をすぐ確認したい。**なぜなら** 対象サイトを切り替える際の誤操作を防ぎたいため。  
3. **管理者として**、権限のないユーザーによるメモ改ざんを防ぎたい。**なぜなら** 運用情報の信頼性を維持する必要があるため。  

## 7. 受け入れ条件（Given / When / Then）
### AC-01: 設定画面での保存
- **Given** Website 更新権限を持つユーザーが対象 Website の編集画面を開いている  
- **When** 500 文字以内の notes を入力して保存する  
- **Then** 保存が成功し、同画面の再表示・再読み込み後も同一 notes が表示される  

### AC-02: 文字数上限
- **Given** Website 更新権限を持つユーザーが編集画面で notes を入力している  
- **When** 501 文字以上の notes を保存しようとする  
- **Then** 保存は拒否され、上限超過を示すエラーが表示される  

### AC-03: 一覧表示（notes あり）
- **Given** notes が設定された Website が存在する  
- **When** Website 一覧画面を表示する  
- **Then** 当該 Website 行に notes が表示され、長文は省略表示される  

### AC-04: 一覧表示（notes なし）
- **Given** notes 未設定の Website が存在する  
- **When** Website 一覧画面を表示する  
- **Then** 当該 Website 行には notes 表示領域が出ない（空表示・不要プレースホルダーを出さない）  

### AC-05: 権限制御
- **Given** Website 更新権限を持たないユーザーが対象 Website を操作している  
- **When** notes を新規保存または更新しようとする  
- **Then** 更新は拒否され、notes の内容は変更されない  

### AC-06: 既存データ互換
- **Given** 既存 Website データに notes が未設定（null/空）が含まれている  
- **When** Website 一覧表示・詳細表示・更新処理を実行する  
- **Then** 例外や表示崩れなく従来機能が継続して動作する  

## 8. 抜け漏れチェック結果
- 課題/対象ユーザー/成功状態: 明文化済み
- 機能要件/非機能要件: 分離して定義済み
- 受け入れ条件: すべて検証可能な Given/When/Then で記述済み
- 権限・上限・未設定データ・一覧表示の例外系: 反映済み
- スコープ外: 明示済み

## 9. 前提・未決事項（疑問点）
1. notes の文字数上限は 500 文字（501 文字以上は保存不可）とする。  
2. 文字数カウントは改行を 1 文字として扱い、全角/半角とも 1 文字として数える。  
3. 一覧での「省略表示」の具体ルール（何文字で省略、末尾記号、全文表示手段有無）は UI 設計時に検討して固定する。
