# US-201 受入条件（人手で定義・固定 / 網羅度計測の基準）

> このファイルは実験の「基準」です。AIには変更させません（各フェーズのプロンプトで編集禁止・読込禁止を指示済み）。
> 受入条件充足率＝この受入条件のうちテストで合格判定できた割合、で計測する。
> 対象: umami（Next.js + Prisma / PostgreSQL）。E2E は Playwright（`pnpm test:e2e`）で検証する。

| ID   | 受入条件 |
|------|----------|
| AC-1 | ウェブサイトにメモを保持する項目が永続化層（`prisma/schema.prisma` の `Website`）に追加され、対応するマイグレーションが `prisma/migrations/` に存在する。既存レコードは NULL/空で移行できる（既存データを壊さない）。 |
| AC-2 | ウェブサイト設定の詳細画面でメモを入力して保存でき、ページを再読み込みしても保存内容が表示される。 |
| AC-3 | ウェブサイト更新 API（`POST /api/websites/[websiteId]`）がメモを受け付け、保存後の値をレスポンスに含む。他の項目（name / domain 等）を同時に更新しても互いを壊さない。 |
| AC-4 | 500文字を超えるメモは保存されず、API は 400 系エラーを返す（UI 側でもエラーが分かる）。500文字ちょうどは保存できる。 |
| AC-5 | ウェブサイト一覧でメモが確認できる。メモ未設定のサイトには何も表示されない（`null` / `undefined` などがそのまま出ない）。 |
| AC-6 | ウェブサイトを更新する権限のないユーザーはメモを更新できない（既存の `canUpdateWebsite` 相当の認可に従い 401/403 相当を返す）。 |
| AC-7 | 既存のユニットテスト（`pnpm test`）と既存 E2E（`tests/e2e/website.spec.ts` 等）が引き続き合格する（デグレなし）。 |

## 計測メモ
- 「上限500文字・超過は保存不可・ちょうどは可」を**正**とする。実装がこの基準と異なる場合は欠陥候補（AC-4）。
- AC-1 は「マイグレーションファイルの有無」と「`pnpm update-db` が通ること」で判定する。
- AC-7 は回帰テスト合格率の観点（デグレ計測）として別枠で記録する。
- 受入条件充足率は AC-1〜AC-7 のうち、テスト（E2E/ユニット）で合否判定できたものの割合で算出する。
