# US-201 E2E テスト設計: ウェブサイトメモ

## テスト方針

US-201 は「ウェブサイト設定情報としての notes」を対象にするため、E2E ではユーザーが触る Settings → Websites と編集画面の主要フローを中心に検証する。API の細部は既存の単体・ルートテストを前提にしつつ、E2E では UI から保存・再表示・一覧表示できること、サーバー側の上限検証と権限境界が壊れていないことを Playwright で確認する。

追加ライブラリはありません。既存依存の `@playwright/test` と既存 E2E ヘルパーを利用します。

## テスト観点

| 観点 ID | 観点 | 確認内容 |
| --- | --- | --- |
| VP-201-01 | 編集画面でのメモ保存 | notes 入力欄に 500 文字以内の値を入力して保存できる |
| VP-201-02 | 永続化と再表示 | 保存後に編集画面を再読み込みしても notes が初期値として表示される |
| VP-201-03 | 一覧表示 | Settings → Websites の対象行に保存済み notes が表示される |
| VP-201-04 | 未入力・空メモの扱い | notes が null/空の場合、一覧に notes 本文を表示しない |
| VP-201-05 | 文字数上限 | 501 文字の notes は UI と API の両方で拒否され、既存 notes を上書きしない |
| VP-201-06 | 既存データ互換 | notes 未設定の Website でも編集画面表示と既存項目更新が継続できる |
| VP-201-07 | 権限 | 閲覧可能だが更新権限を持たないユーザーは notes を変更できない |

## E2E シナリオ

| シナリオ ID | テスト名 | 種別 | 手順概要 | 期待結果 |
| --- | --- | --- | --- | --- |
| E2E-201-01 | saves notes, reloads them, and shows them in the websites list | UI + API setup | notes 未設定の Website を作成し、編集画面で notes を入力して保存する。編集画面を再読み込みし、Settings → Websites に戻る。 | 保存が成功し、再読み込み後の notes 入力欄と一覧の対象行に保存済み notes が表示される。notes 未設定からの更新でも既存項目が扱える。 |
| E2E-201-02 | clears notes and hides them from the websites list | UI + API setup | 既存 notes ありの Website を作成し、編集画面で notes を空にして保存する。Settings → Websites に戻る。 | 保存後の一覧対象行に notes 表示要素と旧 notes 本文が表示されない。API 上も notes は null になる。 |
| E2E-201-03 | rejects notes longer than 500 characters and preserves existing notes | UI + API | 既存 notes ありの Website を作成し、編集画面で 501 文字を入力して保存を試みる。さらに API にも 501 文字を直接送る。 | UI は上限エラーを表示し、API は 400 を返す。既存 notes は上書きされない。 |
| E2E-201-04 | rejects notes changes from team view-only users | API | team-view-only ユーザーを Team Website に追加し、対象 Website を取得できることを確認してから notes 更新を試みる。 | 対象 Website は閲覧可能だが、notes 更新は 401 で拒否され、既存 notes は変わらない。 |

## Playwright 実装メモ

- テスト本体は `tests/e2e/website-notes.spec.ts` に配置する。
- セレクタは既存実装の `data-test` を優先し、notes 入力は `input-notes`、一覧表示は `website-notes` を使う。
- テストデータは各テストで一意の Website/User/Team を API 生成し、`afterEach` で削除する。
- 明示的な sleep は使わず、`waitForResponse` と Playwright の web-first assertions で保存完了・表示状態を待つ。
- 文字数上限は UI エラー表示だけでなく API への直接 POST でも確認し、クライアント側だけの検証になっていないことを担保する。

## セルフレビュー

| チェック項目 | 結果 |
| --- | --- |
| 受入条件の網羅 | AC-201-01 から AC-201-08 まで対応シナリオを割り当て済み |
| E2E の肥大化抑制 | UI は主要フロー 3 本に絞り、権限とサーバー検証は API 経由で安定化 |
| セレクタ安定性 | `data-test` とテーブル行の表示テキストで対象行を特定し、CSS 構造依存を最小化 |
| フレーキー対策 | 保存完了は POST レスポンス待ち、表示確認は `expect(...).toHaveValue/toContainText` を使用 |
| データ独立性 | 一意名・一意ドメインを生成し、Website/User/Team をテストごとに後始末 |
| 依存関係 | 新規ライブラリ追加なし、既存 lockfile バージョン変更なし |
| 制約遵守 | 実装本体と受入条件ファイルは変更対象外 |
