# US-201 要件定義: ウェブサイトメモ

## 背景・目的

umami に登録するウェブサイトが増えると、サイト名とドメインだけでは本番環境・検証環境・依頼元・運用上の注意点などを判別しづらくなる。サイト運用者が各ウェブサイトに自由記述のメモを残せるようにし、設定変更や一覧確認時にサイトの文脈を素早く把握できる状態を目指す。

## 対象ユーザー・ステークホルダー

| 区分 | 説明 |
| --- | --- |
| 主利用者 | umami に複数のウェブサイトを登録・管理するサイト運用者 |
| 関係者 | サイト作成依頼者、運用チーム、管理者 |
| 権限上の関係者 | ウェブサイト設定を更新できるユーザー、更新権限を持たない閲覧ユーザー |

## 成功指標

- サイト運用者が、ウェブサイト編集画面で対象サイトのメモを入力・編集・保存できる。
- 保存済みメモが再読み込み後も保持され、ウェブサイト一覧でも対象サイトの補足情報として確認できる。
- メモ未設定の既存ウェブサイトでも既存操作が継続できる。
- 更新権限を持たないユーザーがメモを変更できない。

## スコープ

### 対象

- ウェブサイト単位で自由記述のメモを保持する。
- Settings → Websites → 対象サイトの編集画面でメモを入力・編集・保存できる。
- ウェブサイト一覧で、メモが設定されているサイトのみメモの存在と内容の概要を表示する。
- メモの最大文字数を 500 文字とし、上限を超える場合は保存させない。
- 既存ウェブサイトのメモ未設定状態を許容する。
- 既存のウェブサイト更新権限に従ってメモ更新可否を制御する。

### 対象外

- メモの履歴管理、差分表示、復元。
- メモ専用の検索、フィルター、ソート。
- Markdown、リッチテキスト、添付ファイル、リンクプレビューなどの拡張表現。
- 複数ユーザーによる同時編集の競合解決 UI。
- メモ更新専用の新しい権限体系。
- ウェブサイト以外のエンティティへのメモ追加。

## MVP 定義

ウェブサイト編集画面で 500 文字以内のメモを保存でき、保存後に再読み込みしても値が保持され、ウェブサイト一覧ではメモ設定済みサイトにのみ省略可能なメモ表示が行われること。既存サイトと権限制御は既存動作を壊さず維持する。

## 機能要件

| ID | 要件 | 優先度 | 根拠 |
| --- | --- | --- | --- |
| FR-1 | ウェブサイトは任意入力のメモを 1 件保持できる。 | Must | サイト名・ドメインだけでは運用上の文脈を識別できないため。 |
| FR-2 | ウェブサイト編集画面で `Notes` ラベルのメモを入力・編集・保存できる。 | Must | 運用者が既存の設定変更導線の中でメモを管理できる必要があるため。 |
| FR-3 | 保存したメモは永続化され、画面再読み込み後も同じ内容が表示される。 | Must | メモは継続的な運用情報として参照されるため。 |
| FR-4 | ウェブサイト一覧では、メモが入力されているサイトに限りメモ内容の概要を表示する。 | Must | 一覧上でサイトの用途や背景を素早く判別したいため。 |
| FR-5 | 一覧表示でメモが長い場合は、視認性を損なわない形で省略表示できる。 | Should | 長文メモにより一覧の可読性が低下することを防ぐため。 |
| FR-6 | メモ未入力のサイトでは、一覧にメモ用の不要な表示を出さない。 | Must | 既存サイトや未設定サイトの一覧表示を煩雑にしないため。 |
| FR-7 | メモは 500 文字以内とし、上限を超える入力は保存できない。 | Must | 過度に長い入力による UI・保存データ・運用負荷を防ぐため。 |
| FR-8 | 既存のウェブサイト更新権限を持たないユーザーは、メモを作成・変更・削除できない。 | Must | メモもウェブサイト設定の一部であり、不正な改変を防ぐ必要があるため。 |
| FR-9 | 既存のメモ未設定ウェブサイトは、編集画面・一覧・保存処理でエラーなく扱える。 | Must | 既存データとの後方互換性が必要なため。 |
| FR-10 | 空文字・未入力・`trim()` 後に空となる入力で保存した場合、メモ未設定として扱える。 | Should | 不要になったメモを削除できる自然な操作が必要なため。 |

## 非機能要件

| ID | 要件 | 優先度 | 根拠 |
| --- | --- | --- | --- |
| NFR-1 | メモの入力検証はクライアント側だけでなく、保存処理側でも 500 文字以内を保証する。 | Must | クライアント制御の迂回による不正保存を防ぐため。 |
| NFR-2 | メモ表示時は既存 UI の安全な文字列表示方針に従い、入力内容がスクリプトとして実行されないこと。 | Must | 自由記述欄により XSS リスクが生じるため。 |
| NFR-3 | メモ未設定の既存データを扱う際、一覧・詳細・更新 API の既存動作を維持する。 | Must | 既存利用者に影響を与えないため。 |
| NFR-4 | ウェブサイト一覧の表示性能を大きく低下させない。 | Should | 一覧は管理作業の起点であり、メモ追加で体感速度が悪化しないことが望ましいため。 |
| NFR-5 | UI 文言・配置・バリデーション表示は既存の Settings / Websites 画面のスタイルに合わせる。 | Should | 既存体験と一貫した操作性を保つため。 |
| NFR-6 | 保存先・フィールド名・型定義・バリデーションは既存の TypeScript / Next.js App Router / zod / Prisma / @umami/react-zen の実装方針に合わせる。 | Should | 保守性と実装一貫性を保つため。 |

## ユーザーストーリー

### US-201-1: ウェブサイトにメモを保存する

サイト運用者として、登録済みウェブサイトにメモを入力・保存したい。なぜなら、サイトの用途・環境・依頼元などを後から判別できるようにしたいから。

#### 受け入れ条件

1. Given ウェブサイト更新権限を持つユーザーが対象サイトの編集画面を開いている, When 500 文字以内のメモを入力して保存する, Then 保存が成功し、編集画面に保存したメモが表示される。
2. Given 保存済みメモがあるウェブサイト, When ユーザーが画面を再読み込みする, Then 保存済みメモが再表示される。
3. Given メモ未設定の既存ウェブサイト, When ユーザーが編集画面を開く, Then エラーにならず、メモ欄は未入力状態として表示される。
4. Given 保存済みメモがあるウェブサイト, When ユーザーがメモを空または空白のみの入力にして保存する, Then 保存が成功し、そのサイトはメモ未設定として扱われる。

### US-201-2: ウェブサイト一覧でメモを確認する

サイト運用者として、ウェブサイト一覧で各サイトのメモを確認したい。なぜなら、詳細画面を開かなくてもサイトの文脈を把握したいから。

#### 受け入れ条件

1. Given メモが設定されたウェブサイトがある, When ユーザーがウェブサイト一覧を表示する, Then そのサイトの行またはカードでメモ内容の概要を確認できる。
2. Given メモが長いウェブサイトがある, When ユーザーがウェブサイト一覧を表示する, Then 一覧の可読性を保つためメモは省略表示されてもよい。
3. Given メモ未設定のウェブサイトがある, When ユーザーがウェブサイト一覧を表示する, Then そのサイトにはメモ内容や空のプレースホルダーを表示しない。

### US-201-3: メモの入力制限を守る

サイト運用者として、メモが長くなりすぎないよう制限された状態で入力したい。なぜなら、一覧や詳細画面の可読性とデータ品質を保ちたいから。

#### 受け入れ条件

1. Given ウェブサイト更新権限を持つユーザーが対象サイトの編集画面を開いている, When 501 文字以上のメモを保存しようとする, Then 保存は失敗し、メモが 500 文字以内である必要が分かる。
2. Given 500 文字のメモを入力している, When ユーザーが保存する, Then 保存が成功する。
3. Given 保存処理に直接 501 文字以上のメモが送信される, When サーバー側で更新処理を行う, Then 保存は拒否され、既存の保存済みメモは不正な値で上書きされない。

### US-201-4: 権限のないユーザーによる変更を防ぐ

管理者として、ウェブサイト更新権限を持たないユーザーにはメモを変更させたくない。なぜなら、メモもサイト設定に紐づく運用情報であり、不正な変更を防ぐ必要があるから。

#### 受け入れ条件

1. Given ウェブサイト更新権限を持たないユーザーが対象サイトを参照できる, When メモを変更しようとする, Then メモは保存されない。
2. Given ウェブサイト更新権限を持たないユーザーが保存処理へ直接リクエストする, When メモ変更を送信する, Then リクエストは拒否され、既存メモは変更されない。
3. Given ウェブサイト更新権限を持つユーザーがメモを変更する, When 保存処理を実行する, Then 既存のウェブサイト更新と同じ権限ルールで保存が許可される。

## 優先度整理

| 区分 | 内容 |
| --- | --- |
| Must | メモの保持、編集画面での入力・保存、永続化、一覧でのメモ表示、500 文字制限、既存サイト互換、既存更新権限による保護 |
| Should | 長文メモの省略表示、空保存によるメモ削除、既存 UI スタイルへの自然な統合、一覧性能への配慮 |
| Could | 入力中の文字数カウンター、一覧でのツールチップ表示 |
| Won't | 検索・フィルター・ソート、履歴管理、Markdown/リッチテキスト、専用権限、同時編集競合解決 UI |

## 前提

- メモはウェブサイト設定の一部として扱い、更新権限は既存のウェブサイト更新権限を再利用する。
- メモはプレーンテキストとして扱う。
- 文字数上限は「500 文字」とする。
- メモ入力欄のラベル文言は `Notes` とする。
- 一覧での省略長や具体的な配置は、既存の Websites 一覧 UI の可読性を優先して決定する。

## リスク・考慮事項

- 既存データにメモが存在しないため、未設定値の扱いを誤ると一覧や編集画面で表示エラーが発生する可能性がある。
- 自由記述欄のため、表示時のエスケープや既存コンポーネントの安全な文字列表示に従わない場合 XSS リスクがある。
- 一覧に長文を表示しすぎると、サイト名・ドメインなど既存情報の視認性が下がる可能性がある。
- クライアント側だけで文字数制限を行うと、直接リクエストにより上限超過値が保存される可能性がある。

## 疑問点・未決事項

- 一覧でのメモ省略表示の具体的な文字数、または全文確認方法は UI 設計時に決定する。
