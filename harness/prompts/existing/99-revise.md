# フェーズ: レビュー指摘の修正（既存プロセス・共通）

直前のフェーズ「**{{PHASE_NAME}}**」の成果物に対して、レビュアーがPR上でコメントを残しました。
**必ず `{{SKILL}}` スキルを使って**、以下の指摘を反映してください。

## 反映するレビューコメント
各行の先頭 `[C1]` `[C2]` … は**参照タグ**です（回答ファイルで使います）。
{{REVIEW_COMMENTS}}

## やること
1. コメントを一件ずつ確認し、該当する成果物を修正する。
2. 各コメントへの対応内容を**回答ファイルに JSON で書き出す**（下記フォーマット）。
3. 指摘が成果物間の矛盾を示す場合は、当該フェーズの成果物側で解消する。

## 出力
### 1) 成果物の更新
- 直前フェーズと同じ成果物ファイルを更新する。

### 2) 回答ファイル `{{RESPONSE_FILE}}`（新規に上書き作成・必須）
参照タグごとに、レビュアーへ返す**簡潔な回答文**を書く。スクリプトがこれを読み、PR上の各コメントへ自動返信する。
```json
[
  { "ref": "C1", "reply": "ご指摘のとおり修正しました。○○を△△に変更しています。" },
  { "ref": "C2", "reply": "こちらは意図的な仕様のため変更していません。理由は〜。" }
]
```
- `ref` は上のコメント一覧の参照タグと一致させること。
- `reply` は日本語1〜3文程度。修正した場合は「何をどう直したか」、対応不要と判断した場合はその理由を書く。
- 提示された参照タグはすべて `reply` すること（漏れなく）。

## 制約（検証の再現性のため厳守）
- **レビュー指摘の反映のみ**を行う。指摘と無関係な変更・リファクタ・新規機能追加はしない。
- 当該フェーズの担当範囲を越えるファイル（後続フェーズの成果物・実装本体など）は変更しない。
- `stories/{{STORY}}/acceptance-criteria.md` は検証用のため**絶対に読み込まないこと**。
- コミット・PRへの返信投稿はスクリプト側で行うので、手動でのコミットや `gh` 操作は不要。
