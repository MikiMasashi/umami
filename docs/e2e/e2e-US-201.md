# E2E テスト設計書 US-201: ウェブサイトへのメモ（notes）追加

このドキュメントは US-201 の E2E テスト観点・シナリオ設計、受け入れ条件との
トレーサビリティ、および Playwright テスト実装のセルフレビューをまとめたものである。

参照した既存成果物:
- `docs/requirements/requirement-US-201.md`
- `docs/specifications/api-specification.md`
- `docs/implementation/implementation-notes-US-201.md`

## 1. テスト戦略・スコープ

テストピラミッドの方針に従い、フィールド単位の詳細な分岐（バリデーション文言、
Prisma への渡し方など）は既存のユニット/コンポーネントテスト
（`src/tests/websites-notes-*.test.ts`, `src/tests/WebsiteEditForm.test.tsx`,
`src/tests/WebsitesTable.test.tsx`）で担保済みであるため、E2E では以下に限定する。

- **クリティカルユーザージャーニー**: 編集画面での入力→保存→再読み込みでの永続化、
  一覧画面での表示/非表示/省略、文字数上限の実運用上の境界（500 / 501 文字）、
  後方互換性（`notes = null` の既存サイト）、権限制御（更新権限なしユーザーの拒否）。
- E2E は UI 経由（Playwright `page`）と API 直接呼び出し（Playwright `request`）の
  2 レイヤで構成し、既存の `tests/e2e/website.spec.ts` / `tests/e2e/api-website.spec.ts`
  の構成・命名規則を踏襲した。
- 権限制御（US-201-6）は「画面操作」「API 直接呼び出し」の両方が要件に明記されているため、
  両レイヤでシナリオを用意した。

## 4. 権限制御シナリオの設計メモ

- 「更新権限を持たないユーザー」の再現には、個人所有サイトの `userId` 不一致では
  なく、チーム所属サイトに対して `team-view-only` ロールのユーザーを割り当てる方式を
  採用した。これは `src/permissions/website.ts` の `canUpdateWebsite` が
  チーム所属サイトの場合に `hasPermission(teamUser.role, PERMISSIONS.websiteUpdate)`
  で判定しており、`ROLE_PERMISSIONS['team-view-only']` が空配列であるため、
  意図的に権限なしユーザーを作れるためである（`src/lib/constants.ts` 参照）。
- 逆に更新権限ありユーザーの確認には `team-member` ロール
  （`ROLE_PERMISSIONS['team-member']` に `websiteUpdate` を含む）を使用した。
- UI 側のシナリオでは、`WebsiteEditForm` に専用の閲覧専用モード（保存ボタン無効化）が
  実装されていないこと（`docs/implementation/implementation-notes-US-201.md` の
  セルフレビューに明記）を踏まえ、「保存操作自体は行えるが、サーバー側の
  `canUpdateWebsite` チェックにより更新が反映されない」ことをアサーションした
  （保存成功トーストが表示されないこと、および API 経由でデータが変更されていないことを確認）。

## 5. Playwright テスト実装

- `tests/e2e/website-notes.spec.ts`: UI 経由のシナリオ（8 テスト）。
- `tests/e2e/api-website-notes.spec.ts`: API 直接呼び出しのシナリオ（10 テスト）。
- 既存の `tests/e2e/helpers.ts` に以下を追加・拡張した（後方互換: 既存の呼び出し元
  `tests/e2e/website.spec.ts` 等の呼び出しシグネチャは変更していない）。
  - `addWebsite` に第5引数 `options?: { notes?; teamId? }` を追加し、レスポンス
    ボディを返すよう変更（既存呼び出し元は戻り値を使用していないため影響なし）。
  - `addUser` / `addTeam` がレスポンスボディを返すよう変更（同上、既存呼び出し元は
    戻り値を使用していないため影響なし）。
  - `addTeamUser` を新規追加（チームへのユーザー追加・ロール設定、
    `tests/e2e/api-team.spec.ts` の既存パターンをヘルパー化）。
- `tests/e2e/fixtures.ts` に `notesFixtures`（500文字ちょうど、501文字、長文、
  通常文字列などのテストデータ）を追加した。
- セレクタは既存実装の `data-test="input-notes"`（`WebsiteEditForm.tsx`）に基づき
  `getByTestId` を使用し、ロールベース・アクセシブルネームで代替可能な箇所
  （トースト文言等）は `getByText` を使用した。実装詳細に依存する脆いセレクタ
  （CSS/XPath）は使用していない。
- 明示的な `sleep` は使用せず、Playwright の web-first assertion（`expect(...).toHaveValue`,
  `toBeVisible`, `toContainText` 等）による自動待機を利用した。
- 各テストは `addWebsite` / `addTeam` / `addUser` で独立したテストデータを作成し、
  `afterEach` 相当の後始末をテスト末尾で明示的に `deleteWebsite` / `deleteUser` /
  `deleteTeam` により行い、並列実行・順序非依存を維持した（API テストのみ
  `test.describe.configure({ mode: 'serial' })` を既存の `api-website.spec.ts` /
  `api-team.spec.ts` の慣習に合わせて指定し、共有の `auth` トークン取得を1回に
  抑えている）。

## 7. セルフレビュー

- **受け入れ条件との対応**: 要件定義書 US-201-1 〜 US-201-6 に記載された全ての
  Given-When-Then（16項目）に対し、上記トレーサビリティ表の通り最低1つの
  E2E シナリオを割り当てた。抜け漏れがないことをチェックリスト形式で確認済み。
- **既存コード・命名規則との一貫性**: `tests/e2e/website.spec.ts` /
  `tests/e2e/api-website.spec.ts` / `tests/e2e/api-team.spec.ts` の
  記述スタイル（`test.describe` の構成、`loginPage`/`loginViaApi` の使い分け、
  `addWebsite`/`deleteWebsite` 等のヘルパー利用、`data-test` 属性ベースの
  セレクタ）を踏襲し、新規パターンを持ち込んでいない。
- **フレーキー耐性**: `sleep` を使用せず、Playwright の自動待機アサーションのみを
  使用。テストデータ（ウェブサイト名・ドメイン名）は各テストで一意な文字列を
  使用し、テスト間の干渉を避けた。ただし `website-notes.spec.ts` の
  「一覧表示」テストは3件のウェブサイトを同時作成するため、他の並列実行中の
  テストが同一 `settings/websites` 一覧に影響を与えないよう、行の特定は
  常にサイト名でフィルタしたロケータ（`table tbody tr` を `name` で `filter`）を
  使用しており、一覧全体の行数には依存していない。
- **権限制御シナリオの妥当性**: `canUpdateWebsite`（`src/permissions/website.ts`）の
  実装（チーム所属サイトはチームロールの `PERMISSIONS.websiteUpdate` 権限で判定）を
  ソースコードで確認した上で、`team-view-only`（権限なし）と `team-member`
  （権限あり）のロールを使い分けて拒否・許可の両ケースを検証している。
- **実行環境上の制約（既知の未検証事項）**: この検証環境には `DATABASE_URL` が
  設定されておらず、Prisma Client 未生成のため実際に `pnpm dev` を起動して
  Playwright テストを最後まで実行することはできなかった
  （`docs/implementation/implementation-notes-US-201.md` に記載の既知の制約と同様）。
  代わりに以下で静的な妥当性を確認した。
  - `npx playwright test tests/e2e/website-notes.spec.ts tests/e2e/api-website-notes.spec.ts --list`
    により全19シナリオが構文エラーなく検出されることを確認済み。
  - `npx tsc --noEmit` で新規・変更ファイル（`website-notes.spec.ts`,
    `api-website-notes.spec.ts`, `helpers.ts`, `fixtures.ts`）に起因する型エラーが
    ないことを確認済み（既存の Prisma Client 未生成に起因するエラーは
    本ストーリー着手前からの環境依存の問題であり対象外）。
  - DB・サーバーが利用可能な環境（CI 等）でのフル実行は今後の検証事項として残る。
- **意図的な欠陥注入**: 行っていない。
