# Architecture Review (US-201)

## 結論
- 承認（既存境界を崩さない拡張として妥当）。

## 懸念点
1. 一覧で notes を表示すると、横幅の狭い画面で可読性が下がる可能性がある。
2. UI 省略ルールが未固定のままだと、実装者ごとの差で検証不安定になりうる。

## 代替案と却下理由
1. **代替案**: バックエンドで省略済み文字列を返す。  
   **却下理由**: UI 表示要件変更に対して API 変更が頻発し、境界責務が崩れる。
2. **代替案**: Notes 編集を別画面/モーダルに分離。  
   **却下理由**: 既存 Website Settings の編集体験が分断され、運用メモ編集の即時性が下がる。
3. **代替案**: 新規権限 `websiteNoteUpdate` を追加。  
   **却下理由**: 現要件は Website 更新権限との同等制御を求めており、権限体系複雑化の便益が小さい。

## 採用時のガード
1. 省略表示は UI コンポーネント内で共通化し、一覧可読性を担保。
2. API・Query・Permission は既存導線を再利用し、変更点を `notes` に限定。
