# E2E テスト設計 US-201: ウェブサイトへのメモ（notes）機能

## テスト戦略

- クリティカルユーザージャーニー（メモの入力・保存・再表示、一覧での表示、文字数上限、権限保護）に
  絞って E2E を設計し、網羅的な入力パターンの検証はコンポーネントテスト側に譲る。
- セレクタは `data-test`（`testIdAttribute: 'data-test'` を `playwright.config.ts` で設定済み）と
  既存の `td[label="..."]` パターンを優先し、実装の内部構造に依存しない。
- テストデータ（ウェブサイト・ユーザー・チーム）は各テストで作成し、`test.afterAll`/各テスト内で
  後始末を行う（既存の `tests/e2e/api-website.spec.ts` 等の作法を踏襲）。
- ファイル構成:
  - `tests/e2e/website-notes.spec.ts`: ブラウザ操作を伴う UI シナリオ
  - `tests/e2e/api-website-notes.spec.ts`: API 直接呼び出しによるバリデーション・権限シナリオ

## テスト観点

1. メモの入力・保存・再表示（永続化の確認を含む）
2. 空メモの保存（未設定として扱われることの確認）
3. 既存ウェブサイト（メモ未設定）の後方互換性（詳細画面・一覧・部分更新）
4. 一覧でのメモ表示（設定あり／省略表示／未設定で非表示）
5. 文字数上限（500文字）のクライアント側・サーバー側バリデーション
6. 更新権限のないユーザーによる改ざん防止（API直接呼び出し、UIでの編集不可）

## 前提とする設計契約（`docs/specifications/architecture-specification.md` 参照）

- 一覧画面: `/settings/websites`、詳細画面: `/settings/websites/{websiteId}`
- `data-test="input-notes"`: メモ入力欄、`data-test="text-notes"`: 一覧行内のメモ表示
- 一覧のメモ列見出しラベルは `"Notes"`（`td[label="Notes"]` でロケート）
- クライアント側の文字数超過エラー文言: `Notes must be 500 characters or less.`
- API: `GET /api/websites/{websiteId}` は `notes`・`canUpdate` を含む。
  `POST /api/websites/{websiteId}` は `notes`（最大500文字、`null`/空文字許容）を受け付ける。
  500文字超は 400、権限なしは 401。
- 一覧でのメモ省略表示: 60文字を超える場合、先頭60文字 + 省略記号 `…` を表示する。
