# Architecture Review (US-201)

## 結論
- 採用: 既存 Website 設定/一覧フローを拡張し、契約固定点を URL・DOM・HTTP に限定。

## 重点レビュー観点
1. テスト容易性: ルート単位エントリポイント + `data-test` 契約で実装詳細依存を回避。
2. レイヤ責務: 省略表示は UI、文字数制約と認可は API、保存は DB に分離。
3. 変更耐性: 子コンポーネント分割や props 署名を契約外とし実装自由度を確保。

## 懸念点
- `data-test` の命名が既存画面で不統一なため、今後命名ガイドの共通化余地あり。

## 代替案と却下理由
- 代替案: 子コンポーネント構成まで設計時に固定。
- 却下理由: 実装フェーズでのリファクタ余地を奪い、レビュー済みテスト固定方針と衝突するため。
