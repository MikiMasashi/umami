# US-201 要件定義書（Website Notes）

## 1. 背景・目的
- **対象ユーザー**: Umami のサイト運用者（複数サイトを管理するユーザー）
- **課題**: サイト名とドメイン情報だけでは、運用用途（本番/検証）や依頼元などの運用文脈を区別しづらい。
- **目的**: 各 Website に自由記述メモ（notes）を持たせ、設定画面と一覧画面の双方で運用文脈を把握できるようにする。

## 2. 成功指標
- サイト編集画面でメモを保存後、再読み込みしても同内容が保持される。
- サイト一覧でメモがあるサイトのみメモ内容が視認できる（長文は省略表示）。
- 権限のないユーザーはメモ更新ができない。
- 既存サイト（notes 未設定）で回帰不具合が発生しない。

## 3. スコープ
### 3.1 対象（In Scope）
- Website に対する `notes` 情報の保持（永続化）
- Website 編集画面でのメモ入力・更新・保存
- Website 一覧画面でのメモ表示（長文省略）
- メモ未入力時の非表示制御
- 500 文字上限バリデーション（上限超過は保存不可）
- 既存権限制御に基づく更新可否の適用

### 3.2 対象外（Out of Scope）
- メモの全文検索機能
- メモの履歴管理・監査ログ追加
- リッチテキスト編集（Markdown/装飾）
- メモのエクスポート/インポート
- 一覧画面でのメモによる並び替え・フィルタリング

## 4. ユーザーストーリー
### US-201
サイト運用者として、登録済み Website にメモを保存・参照したい。  
なぜなら、サイトの運用目的や背景情報を即座に判別したいから。

## 5. 機能要件
| ID | 要件 | 優先度 |
|---|---|---|
| FR-201-01 | Website は任意のメモ（notes）を保持できること。未設定（null/空）を許容すること。 | Must |
| FR-201-02 | Website 編集画面で notes を入力・更新・保存できること。 | Must |
| FR-201-03 | 保存後に再表示・再読み込みしても notes が保持されること。 | Must |
| FR-201-04 | Website 一覧画面で notes が設定されているサイトのみ表示すること。未設定は非表示にすること。 | Must |
| FR-201-05 | 一覧表示では長文 notes を省略表示すること（全文強制表示しない）。 | Should |
| FR-201-06 | notes は最大 500 文字までとし、超過時は保存を拒否すること。 | Must |
| FR-201-07 | Website 更新権限のないユーザーは notes を更新できないこと。 | Must |
| FR-201-08 | 既存 Website（notes 未設定）でも既存機能がエラーなく動作すること。 | Must |

## 6. 非機能要件
| ID | 区分 | 要件 | 優先度 |
|---|---|---|---|
| NFR-201-01 | 互換性 | 既存データ（notes 未保持）を含む環境で後方互換性を保つこと。 | Must |
| NFR-201-02 | セキュリティ/認可 | notes 更新 API/処理は既存の Website 更新権限チェックを必ず通過すること。 | Must |
| NFR-201-03 | 入力検証 | 文字数上限はサーバー側でも必須検証し、クライアント側検証のみへ依存しないこと。 | Must |
| NFR-201-04 | UX | 上限超過時、ユーザーが修正可能な明確なエラーを表示すること。 | Should |
| NFR-201-05 | 保守性 | 実装は既存スタック/実装規約（TypeScript, Next.js App Router, zod, Prisma, @umami/react-zen）に整合すること。 | Must |

## 7. 受け入れ条件（Given/When/Then）
### AC-201-01: メモ作成と永続化
- **Given** Website 更新権限を持つユーザーが対象 Website の編集画面を開いている  
- **When** 500 文字以下の notes を入力して保存する  
- **Then** 保存が成功し、再読み込み後も同じ notes が表示される

### AC-201-02: メモ更新
- **Given** notes が設定済みの Website がある  
- **When** 権限を持つユーザーが notes を編集して保存する  
- **Then** 新しい notes で上書きされ、一覧/編集画面とも更新内容が反映される

### AC-201-03: 一覧表示（表示/非表示）
- **Given** notes あり Website と notes なし Website が混在している  
- **When** Website 一覧を表示する  
- **Then** notes ありの Website のみメモ表示され、notes なし Website にはメモ表示領域が出ない

### AC-201-04: 長文の省略表示
- **Given** 一覧表示可能な長い notes が保存されている  
- **When** Website 一覧を表示する  
- **Then** notes は省略表示され、レイアウト崩れや過剰な占有を起こさない

### AC-201-05: 文字数上限バリデーション
- **Given** 権限を持つユーザーが編集画面で 501 文字以上の notes を入力している  
- **When** 保存を実行する  
- **Then** 保存は失敗し、上限超過であることが分かるエラーが表示される

### AC-201-06: 権限制御
- **Given** Website 更新権限を持たないユーザーがいる  
- **When** notes を新規作成または更新しようとする  
- **Then** 更新は拒否され、データは変更されない

### AC-201-07: 既存データ互換
- **Given** notes 未設定の既存 Website データが存在する  
- **When** 一覧表示・詳細表示・通常運用を行う  
- **Then** エラーなく既存挙動を維持し、必要時のみ notes を追加できる

## 8. 抜け漏れ・整合性チェック結果
- 対象画面（編集/一覧）とデータ永続化を要件化済み。
- 正常系（作成/更新）と異常系（上限超過/権限不足）を受け入れ条件化済み。
- 既存データ互換（notes 未設定）を明示し、回帰リスクを要件化済み。
- クライアント単独検証の抜けを防ぐため、サーバー側検証必須を非機能要件に追加済み。

## 9. 前提・依存
- Website の既存更新権限制御が存在し、notes 更新にも同一基準を適用できること。
- Website 一覧・編集画面は既存の UI コンポーネント体系で拡張可能であること。

## 10. 疑問点（未解決事項）
1. **文字数の定義**: 半角/全角ともに 1 文字として扱い、改行コードも 1 文字としてカウントする。
2. **一覧省略仕様**: 省略表示の閾値（何文字で省略するか）と表示形式（末尾 `...` の有無）は UI 設計時に画面規約に合わせて検討する。
